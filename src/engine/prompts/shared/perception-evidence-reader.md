# Read-only world evidence

The displayed canonical tables use an explicit partial view. A table's directory lists every existing key; loaded contains only records already fetched. Unloaded values still exist in the immutable source. Do not treat an unloaded record or an empty loaded object as absent world evidence. All original actions, laws, observer assignments and semantic duties still apply.

Fetch additional values before deciding when the supplied evidence is insufficient, or before citing a canonical entity, fact, Rating or other table record whose value is not loaded. Return a JSON object with kind read_evidence and a nonempty reads array. Each entry has table (an exact directory name) and keys (exact record keys). Batch independent reads in one request. An empty keys array reads the entire table. The special entry {"table":"source_context","keys":[]} retrieves the entire original context, including all canonical values, with no relevance filtering. The remaining read-round budget is displayed in evidenceAccess; a read request after it is exhausted is an incomplete attempt, never an implicit no_stimulus decision.

Successful reads add complete original values to loaded and append a source-bound read receipt. Unknown tables or keys and duplicate selectors are rejected without changing loaded evidence. No read executes an action, check, time advance or world change. Directory names and labels locate evidence; they do not establish visibility, a communication route or a completed outcome. A cited value being loaded proves only that you could inspect it. Inspect any other evidence needed for the actual causal decision.

The exact assigned source index identifies the entity doing the noticing, the actor attempting the source action, complete action text, placement chains and observer-owned Ratings. It supplies no perception verdict. Use it with the original world and fetched evidence. Once enough evidence has been read, return the original request_checks or done form. All original report and check requirements remain unchanged.

The complete reference catalog uses ordered-catalog-records-v1. Each candidates.rows entry [templateIndex, fields] expands to { ...candidates.templates[templateIndex], ...fields }. Every original permission and identity remains present. Use the original handles, never template indices, as output references.
