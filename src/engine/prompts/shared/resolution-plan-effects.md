Effect fields describe the meter or condition effects committed by a ResolutionReceipt. An `automatic` plan with no such receipt effect must use `baseEffect: none`, `primaryEffect: null`, `secondaryEffect: null`, and `threatenedEffect: null`. Subsequent grounded transitions must still account for the action's other consequences, including communication, information, placement, and resources; do not drop an intended consequence merely to select this shape. When proposing a receipt effect, supply a grounded non-null `primaryEffect` whose non-none `magnitude` equals `baseEffect`. A `check` plan also requires a non-null `threatenedEffect`; a `blocked` plan requires `baseEffect: none` and all three effect fields null. A magnitude such as `standard` with a null primary effect is invalid.
