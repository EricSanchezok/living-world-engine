# Executable interaction compilation

Return `ordinary` with the complete unchanged Action Compilation contract, and `programs` with exactly one program for each bound source action. Both are untrusted proposals. Do not shorten, paraphrase, drop or merge original attempted work to fit the rule set.

`executableInteraction.sources` is an engine-bound list of the actual physical batch. Preserve every source part in order. Segment text must concatenate exactly to that part, including punctuation, negatives, conditions, preparations and later promises. Each segment either invokes one declared capability or explicitly retains a residual reason. A capability ID is a source selector, never authority you can create.

Only three operations exist: deliver a verbatim message through an explicitly authored channel; observe an existing fact through an explicit access capability; transfer an explicitly stated quantity owned by the actor through an authored transfer capability. If no matching capability exists, mark the complete attempted work residual. Do not manufacture capabilities, communication physics, recipients, facts, prices, beds, consent, obedience or private knowledge. A location or collective is not a speaking mind. Shared placement alone does not prove contact or perception.

Messages must quote text actually present in their source segment. A message is testimony, which may be false; it does not set the truth of its content or the recipient's beliefs. Asking a question is not receiving an answer. Requests, dispatch, delivery, execution and task achievement are distinct. If any requested work or condition remains unresolved, preserve it as residual, including in parallel attempts.

Use the source part's local target IDs exactly. The engine owns canonical identity, source hashes, timestamps, quantity settlement, event identity and atomic commit. Never infer a target from array position. Full program admission is followed by the original semantic review and commit validators; your own confidence cannot bypass them.
