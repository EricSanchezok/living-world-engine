# Screen Semantic Drafts Before Report Materialization

## Status

Accepted
Class: testing

## Context and Problem Statement

The grouped source index still produces incorrect source interpretations and a no-stimulus result whose explanation explicitly establishes present access. Better mechanical acceptance has not yielded a correct complete perception wave.

## Decision Drivers

- Diagnose semantic understanding independently of check and receipt construction.
- Keep the complete world and every assigned relationship available.
- Measure additional-stage feasibility before implementing a production pipeline.
- Preserve unknown judgments and negative outcomes.

## Considered Options

1. Continue adjusting the canonical report prompt.
2. Screen a semantic-only draft before designing delayed report materialization.
3. Implement a two-phase runtime immediately.

## Decision Outcome

Select option 2 as a diagnostic. Keep the same complete source and assignment groups, replacing only the role's output task and the associated instructions/schema. Source identities remain mechanically checked. Draft acceptance is not canonical perception acceptance, and this experiment creates no world result. The earlier explicit assessment/check protocol remains separate negative evidence.

## Pros and Cons of the Options

Option 1 preserves the existing call structure but does not isolate the ability to interpret the world without simultaneously constructing checks and local identities. Option 2 exposes that necessary condition with a bounded experiment, at the cost of testing a task bundle and providing no direct player speed claim. Option 3 could exploit a successful draft but prematurely adds sequential inference and commits to an unproven representation.
