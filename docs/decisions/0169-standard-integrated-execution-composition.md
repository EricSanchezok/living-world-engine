# Standard integrated execution composition

Artifact-Version: 1

## Status
Accepted
Class: architecture

## Context and Problem Statement

The maintained runtime contains reversible compilation, source-bound planning, shared-context batching and observation evidence support, while the ordinary WorldHost default selects the basic composition. Default instances therefore do not exercise the integrated engine selected for ongoing gameplay development.

## Decision Drivers

- Make ordinary new games use one explicit, reproducible integrated configuration.
- Preserve complete action meaning, context, strict validation and non-thinking inference.
- Keep unqualified optional experiments out of the standard selection.
- Distinguish default adoption from semantic or latency certification.

## Considered Options

- Keep the basic host default and require private experiment configuration for gameplay.
- Enable every available candidate option.
- Select the integrated composition through the production registry and preserve explicit control construction.

## Decision Outcome

The production algorithm layer owns the standard integrated composition. WorldHost pins it for new ordinary instances, while stored producers and explicit control compositions retain their identities. The selected tree uses existing Role implementations and their canonical validators; no separate game-execution implementation or save migration is introduced. The bundled model catalog owns the tested DeepSeek Flash profile, non-thinking inference and transport limits.

Default adoption is an engineering rollout. Known temporal interpretation and observation-evidence failures remain limitations; deterministic checks and replay equality do not establish general semantic success or a continuous-play latency target.

The production browser fixture exposed a small-catalog retrieval failure before HTTP: ten required references could not fit an eight-reference proportional budget. Relational RRF v2 therefore treats the mandatory union as the budget floor and records any expansion. Rejecting these worlds or dropping required references would break ordinary gameplay; enlarging every budget would unnecessarily change large-world retrieval. This correction is versioned separately from the previously tested integrated tree, and its extra references are not counted as historical compression gains.

## Pros and Cons of the Options

Keeping the basic default avoids a rollout but leaves normal gameplay disconnected from the integrated work. Enabling all candidates combines incompatible or unqualified behavior. An explicit standard tree exposes the selected work through ordinary entry points and preserves reproducibility, at the cost of adopting a still-evolving engine whose full gameplay acceptance remains incomplete.
