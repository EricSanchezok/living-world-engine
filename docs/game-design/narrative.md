# Open creation and participant narration

This reference owns the expression and presentation boundaries approved in [Spec 0183](../specs/0183-open-actions-immersive-narrative.md) and [Spec 0184](../specs/0184-conversational-continuity-and-recovery.md), implemented by [direct execution](direct-runtime.md), [`narrative/outbox.ts`](../../src/server/narrative/outbox.ts) and WorldHost. Public API v15 exposes saved prose and separate time, source revision, activity and service-pause metadata.

Narrative ownership is divided into [saved contracts](../../src/server/narrative/contracts.ts), [authorized scene evidence](../../src/server/narrative/scene.ts), [paragraph publication](../../src/server/narrative/publication.ts) and the durable outbox. WorldHost schedules model work and persists published segments; the outbox registers and coalesces work inside world transactions without model calls. Publication checks share one instruction and receipt context per batch. Individual questions carry only their paragraph index and semantic focus; every existing check remains present.

## Creative authority

`ActionExpression` contains an attempt, optional literal utterance and observable manner. Its creation context belongs to one actor: local identities, private evidence, personality, relationships, goals and the actual conversational move. NPC wording comes from the creation model. An ordinary spoken reply receives words without unselected physical business; the action decision can separately select a meaningful gesture or delivery. Player expression preserves explicit quotations and separates stage directions from words. A physical action may carry simultaneous words; the same event delivers and records them. A quotation intended for a later step is not spoken during an earlier approach. Neither expression nor player input directly changes canonical state.

For autonomous speech, the expression request also supplies the authorized local recipient catalog. The creator may bind the actual listener together with the words; omission retains the proposed listener. Code resolves that local key before constructing the action and delivering its utterance. Player-controlled expressions and other action kinds keep their existing bindings. Malformed output receives one targeted format correction with both completion audits retained; a transport or service failure does not enter that loop. Explicit null words permit intentional silence, while an empty object does not complete expression generation. See [decision 0238](../decisions/0238-bind-spoken-replies-to-their-actual-listener.md).

Requested reports receive the character's latest observed property values and actual holdings. A recorded attempt is not evidence of its intended result. Explicitly requested deception remains expressible; ordinary reporting cannot infer completion from an attempted action alone.

The first successful private inspection caused by a player's addressed or broadcast speech preserves that speech as the cause for one further NPC decision, even when the inspection's semantic progress says complete. The NPC can report, decline or wait; code does not force speech. Intervening background remarks cannot replace this retained cause. A second inspection under that same cause uses the ordinary progress and no-progress rules.

The private action view identifies the received interaction being answered as `respondingTo`. It is projected only from that actor's retained observations of the causal event. Unknown or forgotten events produce no such entry; the causal pointer never imports an unheard question or another actor's hidden knowledge.

With creation enabled, player-language interpretation uses the pinned fallback decision profile, DeepSeek by default, through the coherent player reading contract and private projection. Jev handles autonomous action selection and world adjudication. Disabling creation retains the native ordinary-action path. This route is recorded as a normal participant interpretation request, not a context fallback; every request remains included in usage and latency.

A structurally readable interpretation with missing or invalid parameters on its selected branch receives one targeted correction against the original input and catalog. Unused branches remain exempt. Both attempts stay in the action audit, including when correction fails; transport and service-cap errors retain their existing failure handling. No effects execute before a bound reading is available.

The same reading selects a literal speech source. A wholly spoken input can bind `input`, causing code to copy the complete submitted words and ignore any generated replacement. A request containing delivery instructions, gestures or an instruction to ask/say instead binds its actual words and manner separately. Explicit quoted spans retain their own keys. Described speech and stage directions can still use authored wording. Resolving meaning and listener does not require rewriting an elliptical question into a new promise or plan.

With creation enabled, a new player use/change operation without a learned capability receives a concrete expression using known procedures and tools. It remains an attempted operation for adjudication. Learned capability reuse and saved ongoing activities retain their execution path without mandatory expression generation.

World effect representation distinguishes an actual existing property/procedure, a missing qualitative result requiring extension, a newly performed instantaneous method without a continuing condition, and a requested end state already established by evidence. Ordinary posture or temporary use may require a new property even when the behavior is familiar. The no-change choice can yield a completed-method receipt only when the separate outcome also succeeds; an unconfirmed requested effect remains partial and an impossible attempt remains failed. The ledger and perception retain the method without inventing a property, resource debit or completed repair. An already-satisfied state produces an explicit no-repeat receipt. Holding, posture and ongoing contact require a continuing property even if their intended wider benefit fails.

World adjudication can request a `WorldExpansionDraft` for missing scene content. Player exploration, including recipient discovery at a known search location, also invites a draft so that a partial initial catalog does not prevent an ordinary discovery. An already established scene can return an empty draft; inventory inspection does not require this invitation. The draft names new entities, optional character settings, qualitative facts and local occurrences. Code supplies stable IDs, placements, public appearance facts and private initial cognition. A bound scene, actor, target or tool accepts either its role alias or its exact canonical ID. Placements may reference another new entity, with parents created before their contents and cycles rejected. A new actor knows its actual initial place. One local Jev request judges both admission against established facts, access, materials and chronology, and whether every newly described person or independently usable object has an entity entry. Coverage questions bind each appearance, fact or event to the actual declared inventory within the same request; the free-form audit summary is excluded from admission. Integral surfaces and clothing used as appearance need no separate entity. A missing entry receives one targeted correction, sharing the same two-attempt limit as structural correction. No draft effects are committed before admission. Mechanical checks still own references, quantities and atomicity. New actors receive goals and a ready intention in the same event. Capability declarations use the existing reusable capability path. World creation receives the complete identity/location directory; admission receives its normalized name matches for the draft alongside complete local evidence. The declared inventory appears once in shared decision context. Architectural surfaces and figurative comparisons do not imply new portable objects. These inputs preserve established named people and places; this directory is excluded from actor and participant projections. Its dependency records names, kinds, lifecycle and placements without invalidating on unrelated descriptive edits.

Expansion fills unsettled space or records a new arrival, discovery or occurrence. It cannot overwrite an established property through the expansion channel. Resource production and consumption use authorized mechanisms. A failed expansion retains a permitted observation of existing facts as a partial result, while an action requiring the missing content stays blocked; generated proposals are retained in the invocation evidence. The [world format](script-format.md) owns authored appearance and narrative preferences.

Expansion descriptions remain proposal audit data. Only materialized additions enter world effects and perceptible facts; the free-form description never becomes an action receipt. Preparatory observation and waiting do not establish later dialogue or gestures. The selected speaking action owns its expression request; an independent empty speech parameter cannot silently replace it with waiting.

## Frozen scenes and ordered prose

[`ParticipantDiscourse`](../../src/engine/contracts/discourse.ts) reconstructs the player's shared conversational context from that participant's arrival and published paragraphs. It records stable local identities, the words used to refer to them, exact delivered speakers, recent complete exchanges and unresolved requests. An entity known by the controlled Agent is not thereby introduced to the reader. Each paragraph persists explicit entity-reference metadata; a narrator reference is resolved against the frozen scene's local identities before publication. The displayed words omit this markup. Revealed names and later pronouns can refer to the same identity. The projection is reproducible after reload without model work and does not expose canonical bindings or another Agent's cognition.

Input interpretation and narration consume this same projection. The normal interpretation batch distinguishes a presentation clarification from speech or action in the world. A clarification of existing information completes through a presentation record with no action frame, delivered speech, new perception or elapsed physical time. Its answer uses the same durable narrative outbox. Ordinary failed interpretation or adjudication registers a recovery beat from saved progress; when service remains available the narrator explains the unresolved request without fabricating a physical obstacle. A typed service cap takes the separate deterministic pause path.

A newly failed NPC response directly caused by the participant's committed action also registers a recovery beat for that submission. Its source retains the earlier committed observations and identifies the interrupted response boundary. It does not expose an unexecuted NPC intention or reinterpret the failure as silence, refusal or an unheard question. Unrelated background failures do not generate participant recovery text.

World adjudication distinguishes delivery from the recipient's ability to see the actor. A heard-only encounter supplies a local voice identity and actual words. Visible appearance and gesture require established sight; public appearance facts can then support a recognizable introduction. Secret identity and motives remain outside this perception channel.

World persistence registers pending `NarrativeBeat` work in the same instance transaction as the committed world result. A `ScenePacket` contains that participant's observations, perceptible details, actual delivered speech, relevant private evidence and requested action. The original request remains audit data and is excluded from both prose creation and the publication check. Executed observations supply narrative focus. Ordinary narration never receives the canonical world or another actor's cognition. Testimony and inference remain attributed; an NPC's words do not establish their truth.

Each participant's beats retain chronological order. Fresh observations for the same submission can join an unstarted beat; a started beat freezes its source hash. Further events form the next beat. World simulation and model computation remain separate, so unrelated model work cannot retroactively write a past event.

An unstarted beat containing only successful delivered speech can publish the exact attributed words directly when its speakers and visible details have already appeared and no accompanying manner is recorded. Literal player dialogue must equal the submitted input. New introductions, changed details, physical actions, stage directions, clarification and recovery retain creative narration. This direct path persists ordinary ordered segments and local mentions, releases the same feedback window and records zero narration requests rather than a fictitious model producer. [Decision 0234](../decisions/0234-delivered-dialogue-and-receipt-only-narration.md) owns this choice.

Normal narration receives new execution receipts and published discourse, with historic raw requests and redundant old action memories removed from its presentation context. Clarification and recovery retain their question and executed progress. The creator may emit a brief source reading before paragraphs; it is diagnostic, is not displayed and grants no world effects.

The creation gateway forwards streamed JSON text while retaining terminal provider usage. Complete paragraphs pass independent continuity, material, agency, evidence, speech and reference questions in one text-decision batch through the instance's fallback profile, DeepSeek by default, for unsupported interactive content, changed outcomes, player agency and intelligible references before receiving stable sequence numbers and being persisted. Publication uses a closed evidence-comparison instruction profile; accurately attributed delivered lies remain valid dialogue. This check is diagnostic evidence, not a guarantee of prose correctness. New factual errors trigger the same single continuation allowance as transport failures; harmless phrasing is allowed. SSE notifies readers only after persistence. A reconnect reads those same segments. Delivered speech references are replaced with exact utterances by code. Before publication, code checks multiplicity and the recorded speech order; a later answer cannot appear before an omitted earlier question. Delivered dialogue must be present in full. Literal words are not reparsed as entity markup. The publication decision checks attribution and other quotations, including signs and labels; punctuation alone does not force literal substring matching. The narrator selects focus, rhythm and detail from established content, leaving new interactive objects, characters and state changes to world creation.

GET, Inspector reads and SSE subscriptions create no model requests. Startup resumes pending work from its saved prefix. A failed prose attempt permits one continuation; after two attempts a factual fallback retains world outcomes and already published text. A fallback after a published prefix supplies missing results or utterances without repeating the scene details. A beat cannot complete while delivered speech is omitted. The reply deadline is held while required feedback is pending and starts when it is ready. Simulation deadlines continue to follow world time.

## Evidence and measurement

Inspector step detail includes frozen sources, segment status, attempt count, execution IDs, producer profile/model/prompt, publication decisions and generation errors. Narration uses separate Ledger executions; request, response, usage and price evidence remains available through the shared invocation list. Time and progress are rendered outside the prose body.

[`immersive-narrative.ts`](../../scripts/experiments/immersive-narrative.ts) runs development, frozen confirmation and continuous sessions through WorldHost with persisted replay and restart checks. It records first saved paragraph and complete feedback separately, retaining full prose, world state and the same-event observation text. These timings become useful-feedback measurements only after content review. The paid transport shares the append-only browser budget; an authorized tranche does not erase historical charges or unknown reservations.

Native fee reservations cover at least 65,536 input tokens and expand to the complete request's byte bound plus serialization allowance. This fee ceiling does not determine context eligibility or force a model fallback. Settlement failures retain returned usage and request/response hashes for review. If historical response usage was lost, a reviewed quarantine may increase its conservative hold, retaining the original entry and one actual request count. It cannot reduce the hold or record invented usage; the interrupted trial stays closed.

If a prospective send cannot fit token or monetary capacity while other sends are in flight, the live transport waits for an active reservation to settle and checks the same limits again. Streamed capacity is retained through terminal usage. Waiting creates no reservation or HTTP request and respects cancellation and the experiment stop condition. Historical holds are never released by this queue; unknown usage, request exhaustion and capacity that still does not fit after active sends finish retain their original failure paths.

An explicit human authorization can remove a named phase's aggregate token limit through the existing append-only budget journal. Effective limits and the authorization evidence appear in its summary. Token usage and monetary holds remain measured; this operation grants no currency or request capacity and resolves no unknown usage. [Decision 0239](../decisions/0239-record-explicit-token-limit-removal.md) defines the accounting boundary.

The production native profile permits a 4 MB serialized request, matching the creation/fallback wire guard. This is transport protection, not a token estimate. An actual provider context rejection transfers the complete shared-state batch to its configured fallback once. These batches do not contain per-question dependency projections, so dividing the question list cannot establish that their shared state fits. A missing fallback preserves the actual failure without resending the same oversized state. Capability expressiveness considers authored random procedures as well as properties; describing operating steps does not by itself require a second result concept.

## Receipt interpretation

The player interpretation batch supplies a conditional continuation answer for each ordinary action branch. Code uses only the executed branch: approaching, looking, speaking and transferring retain separate completion meanings. These answers use the same authorized private context and request, adding questions rather than another request for every action. Shared action policy appears once in that context. An explicit transfer authorization paired with speech or waiting receives one dependent resolution; a quotation or promise remains words. Reference resolution uses published exchanges, delivered speakers, previous searches and current corrections together. A previous unsuccessful search does not mechanically override the current addressee.

Literal Chinese or Arabic duration spans are candidates for the same interpretation batch. The chosen duration must belong to the selected next action; quoted deadlines, questions and later clauses do not authorize waiting. A completed wait remains a receipt when the following observation is selected. Ordinary actions use the world timing profile when no explicit duration belongs to them.

Narrative evidence replaces attempted-action summaries with executed outcomes and observed fact or quantity lines. Speech-only receipts omit proposed physical verbs; historical observation memories use the same source-observation projection. Raw attempts remain in the frozen audit source. The packet includes the participant's latest observed properties, which take precedence over older appearance descriptions when state changes. Merged unstarted packets refresh those properties and known entities. Publication questions bind the current executed actor, action type, status and receipt directly.

Expansion admission compares new characters with bound and matching existing identities in the same batch. Legitimately distinct namesakes remain possible. An existing authored fixed fixture, described in public appearance facts, does not require a duplicate entity from an unrelated addition. New portable objects and new people retain their admission requirements. Missing content and duplicate identities share one directed correction allowance.

An unstarted beat containing only the player's unspoken approach, observation or reflection can wait while that same running request has an immediately ready continuation. An own-speech beat can likewise wait for an immediately ready model response caused by that submission. Its next committed observation joins the same source. Ongoing admitted activity, failed tasks and terminal or paused runs remain publishable; unrelated background conversation does not hold a beat. When a service pause prevents further generation, the same persistence operation settles queued beats from their committed receipts. A pending NPC reply cannot conceal an already delivered player question. The pause retains its separate status, freezes the reply clock and permits no model calls on reads or restart. This groups prerequisite checkpoints and immediate exchanges without delaying an unrelated participant or replacing the durable outbox. See [decision 0233](../decisions/0233-coalesce-immediate-replies-before-publication.md). A factual fallback preserves executed delivery manner and exact delivered words, and expresses actual resource handovers directly with their amounts and senders.

### Current publication task

The narrator and publication check share a task containing new observed receipts, current delivered speech, text already published for the submission and local identities requiring a first introduction. ScenePacket snapshots complete current self-holdings through the authorized participant perspective. Current receipts and observed properties establish facts; published discourse resolves references and supplies continuity. Earlier requests and prose do not authorize new actions or override current inventory.

A packet containing only the participant's speech explicitly marks that scope for narration and publication. It supplies the actual words and their requested delivery; reactions, silence and refusal require separate observed evidence. First narrative mention identifies an existing person without implying a new arrival. Player interpretation distinguishes a direction to perform an act from an instruction to say something, and establishes a conditional request's prerequisite from evidence before selecting its physical branch.

A recovery packet also retains preceding committed observations from the same submission. Its no-new-action boundary applies only to the interrupted next step; the narrator preserves earlier elapsed waits, payments and other effects and identifies the remaining part for retry. Pending merged scenes refresh their location alongside their latest boundary and properties. Hearing actual speech is adjudicated separately from willingness to answer; a lack of confirmed delivery does not establish deliberate refusal.

## Perceived action relations

Each scene receipt retains locally known action targets, instruments, quantities, duration and addressing. These relations distinguish a speaker from their addressee without importing canonical identities. Addressed recipients and nearby witnesses receive only the speech and behavior the local perception decision admits; an addressee is not an exclusive audience. Their evidence identifies the visible addressee. Actual observers receive an admitted expressive gesture in their evidence; unheard or unseen expression stays outside their perception. Narrative publication uses current holdings and concrete shortage receipts, keeps exact delivered words once per delivery, and addresses the participant in second person.

### Language context and reference anchors

The player interpreter receives chronological pairs of earlier inputs and published feedback. An NPC receives a separate spoken timeline from its own retained delivered observations, with speaker, addressee and actual words. The active causal interaction remains explicit. Neither projection imports canonical identity bindings or another subject's private knowledge. The acting participant's current bound method or inspection focus remains in its own receipt; other observers do not receive that private purpose. Narration uses this focus to select actual findings without treating the attempt as completion.

A published exact speech reference also anchors its known local speaker, even if the prose paraphrases the display label. A unique literal delivered quote can establish the same anchor; ambiguous identical quotes cannot select a speaker by guesswork. These text surfaces identify where the voice appeared, not a newly learned personal name.

A fresh interpretation that requests no operation or speech receives a clarification instead of silent completion. It creates no action, delivered words or elapsed time. An incompatible fresh completion that still selects an executable operation retains targeted correction. Semantic profiles and their fixed inference settings are owned by the [model gateway](model-gateway.md).

### Continuation and known work

The publication check receives the already saved paragraphs of the current beat as well as earlier discourse. The first complete paragraph starts publication immediately; later paragraphs completed while its check is running join one subsequent batch. A wholly redundant paragraph can be skipped without a new generation request or a rewrite of saved text; mixed repetition and new content receives the bounded continuation repair. With a nonempty immutable prefix, repair asks only for the unpresented remainder. With no published text, repair explicitly replaces the rejected draft with the complete scene. Both tasks list still-unpublished delivered lines by occurrence, including identical words delivered more than once. Rejected text never counts as publication. Nested arrays containing ordered paragraph strings are flattened losslessly in both the stream reader and final parser; nontext content remains a format error. An empty continuation can finish an already presented result, but an initial empty response cannot finish a beat.

ScenePacket includes only the participant character's own known goals and duties alongside actual receipts and current properties. This supports questions about remaining work without importing another actor's private goals or treating an intention as completed work. Missing reports and unspecified partial results remain limits on knowledge; they do not establish inaction or an invented physical cause.
