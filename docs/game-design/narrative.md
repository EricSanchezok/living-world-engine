# Open creation and participant narration

This reference owns the expression and presentation boundaries approved in [Spec 0183](../specs/0183-open-actions-immersive-narrative.md), implemented by [direct execution](direct-runtime.md), [`world-narrative.ts`](../../src/server/world-narrative.ts) and WorldHost. Public API v14 exposes saved prose and separate time, source revision and activity metadata.

## Creative authority

`ActionExpression` contains an attempt, optional literal utterance and observable manner. Its creation context belongs to one actor: local identities, private evidence, personality, relationships, goals and the actual conversational move. NPC wording comes from the creation model. Player expression preserves explicit quotations and separates stage directions from words. A physical action may carry simultaneous words; the same event delivers and records them. A quotation intended for a later step is not spoken during an earlier approach. Neither expression nor player input directly changes canonical state.

Requested reports receive the character's latest observed property values and actual holdings. A recorded attempt is not evidence of its intended result. Explicitly requested deception remains expressible; ordinary reporting cannot infer completion from an attempted action alone.

With creation enabled, a new player use/change operation without a learned capability receives a concrete expression using known procedures and tools. It remains an attempted operation for adjudication. Learned capability reuse and saved ongoing activities retain their execution path without mandatory expression generation.

World adjudication can request a `WorldExpansionDraft` for missing scene content. Player exploration, including recipient discovery at a known search location, also invites a draft so that a partial initial catalog does not prevent an ordinary discovery. An already established scene can return an empty draft; inventory inspection does not require this invitation. The draft names new entities, optional character settings, qualitative facts and local occurrences. Code supplies stable IDs, placements, public appearance facts and private initial cognition. One local Jev decision admits a nonempty addition against established facts, access, materials and chronology. Mechanical checks still own references, quantities and atomicity. New actors receive goals and a ready intention in the same event. Capability declarations use the existing reusable capability path. World creation and its admission decision receive an identity/location directory to preserve established named people and places; this directory is excluded from actor and participant projections. Its dependency records names, kinds, lifecycle and placements without invalidating on unrelated descriptive edits.

Expansion fills unsettled space or records a new arrival, discovery or occurrence. It cannot overwrite an established property through the expansion channel. Resource production and consumption use authorized mechanisms. A failed expansion remains a local blocked outcome; generated proposals are retained in the invocation evidence. The [world format](script-format.md) owns authored appearance and narrative preferences.

## Frozen scenes and ordered prose

World persistence registers pending `NarrativeBeat` work in the same instance transaction as the committed world result. A `ScenePacket` contains that participant's observations, perceptible details, actual delivered speech, relevant private evidence and requested action. The authoritative prose evidence excludes the original request; the prose model receives that request separately as attention guidance. The publication check receives only executed action evidence. Ordinary narration never receives the canonical world or another actor's cognition. Testimony and inference remain attributed; an NPC's words do not establish their truth.

Each participant's beats retain chronological order. Fresh observations for the same submission can join an unstarted beat; a started beat freezes its source hash. Further events form the next beat. World simulation and model computation remain separate, so unrelated model work cannot retroactively write a past event.

The creation gateway forwards streamed JSON text while retaining terminal provider usage. Complete paragraphs pass a focused text decision through the instance's fallback profile, DeepSeek by default, for unsupported interactive content, changed outcomes and player agency before receiving stable sequence numbers and being persisted. This check is diagnostic evidence, not a guarantee of prose correctness. New factual errors trigger the same single continuation allowance as transport failures; harmless phrasing is allowed. SSE notifies readers only after persistence. A reconnect reads those same segments. Delivered speech references are replaced with exact utterances by code. Direct quotations must match delivered words or literal text in authorized observations and memories, including signs and labels. Delivered dialogue must still be present in full; contextual attribution is checked by the publication decision. The narrator selects focus, rhythm and detail from established content, leaving new interactive objects, characters and state changes to world creation.

GET, Inspector reads and SSE subscriptions create no model requests. Startup resumes pending work from its saved prefix. A failed prose attempt permits one continuation; after two attempts a factual fallback retains world outcomes and already published text. A fallback after a published prefix supplies missing results or utterances without repeating the scene details. A beat cannot complete while delivered speech is omitted. The reply deadline is held while required feedback is pending and starts when it is ready. Simulation deadlines continue to follow world time.

## Evidence and measurement

Inspector step detail includes frozen sources, segment status, attempt count, execution IDs, producer profile/model/prompt, publication decisions and generation errors. Narration uses separate Ledger executions; request, response, usage and price evidence remains available through the shared invocation list. Time and progress are rendered outside the prose body.

[`immersive-narrative.ts`](../../scripts/experiments/immersive-narrative.ts) runs development, frozen confirmation and continuous sessions through WorldHost with persisted replay and restart checks. It records first saved paragraph and complete feedback separately, retaining full prose, world state and the same-event observation text. These timings become useful-feedback measurements only after content review. The paid transport shares the append-only browser budget; an authorized tranche does not erase historical charges or unknown reservations.

Native fee reservations cover at least 65,536 input tokens and expand to the complete request's byte bound plus serialization allowance. This fee ceiling does not determine context eligibility or force a model fallback. Settlement failures retain returned usage and request/response hashes for review. If historical response usage was lost, a reviewed quarantine may increase its conservative hold, retaining the original entry and one actual request count. It cannot reduce the hold or record invented usage; the interrupted trial stays closed.
