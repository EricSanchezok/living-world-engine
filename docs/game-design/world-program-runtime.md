# World Program Runtime

The world program kernel lives in [`src/engine/events/kernel.ts`](../../src/engine/events/kernel.ts). It is independent of private Agent programs. The default `decision-event@6` producer runs through WorldHost, SimulationEngine, CanonicalCommitter and history replay. [Spec 0181](../specs/0181-jev-decision-event-engine.md) defines its replacement and qualification contract.

Private expansion allowances renew on distinct private information. New identifiers for identical testimony or duplicate observation metadata do not renew them. The complete evidence remains available to model decisions and dependency validation. Invalidated program versions and programs that ended without visible progress or goal evidence require a revised definition; a controller pause permits reuse. World event success, program completion and goal completion remain separate.

## Compilation and authority

`compileWorldProgram` projects canonical physical resources without Agent cognition or identity-binding maps. DeepSeek returns an immutable source-bound rule and parameter bindings. Sources include the world contract, laws, mechanics, and authored seed facts from the pinned history base. Runtime fact changes affect read dependencies without rewriting their authored source. Runtime testimony is evidence, not new rule authority. Admission checks exact source identities, parameter ownership, expression dependencies, effect shapes, and branch references. One targeted repair is allowed. Exhaustion retains a recoverable failure and all invocation evidence.

Effects are JSON templates. Dynamic leaves use `$expression` or `$text`; `$literal` escapes literal data. Code materializes templates into typed world operations. Generated rules cannot own time advancement or initialize quantities to bypass conservation. Fact and condition provenance is supplied by the kernel. Speech delivery must match the concrete utterance authored before the attempt.

WorldProgram v5 includes trusted `mechanics` invocations on each branch and declares the shared facilities occupied by its execution. The compiler receives the selected package's canonical input contracts. `$attempt` binds a current action field without freezing an old action identity into a reusable rule. The existing rule registry derives quantity transfers and production/consumption from explicit action amounts, existing quantities or committed randomness, and rejects direct raw numeric operations under `core-resolution`. The candidate, commit record and replay retain the actual invocation, source and derived operations. Quantity dependencies bind the relevant holders and source records, so changing an unrelated entity does not invalidate the event. Named resolution templates bind grounded means, actual targets, difficulty, risk and magnitude bands to the existing resolution contract. Code derives D20 requests and effect receipts; branches reference admitted resolution IDs instead of generating numeric meter or condition operations. Automatic effects use the same trusted package without a draw. Check results use the durable random reservation and remain separate from private observations. The kernel checks target/meter/profile ownership and complete primary and threatened effects before random authorization, and records finalized plans, receipts and mechanics with the physical event. New timed conditions begin at that execution boundary.

The repository injects the same trusted rule registry into compilation, mechanical preparation, canonical commits, execution-reference persistence, instance recovery and Inspector or recorded-algorithm replay. Selected package versions must exist at every entry. Registry implementations remain server services rather than serialized model authority. Source identity arrays use stable ordering, including after content-addressed JSON persistence.

Rule packages separate operation-shape validation from validation that reads world context. The core package's raw-effect restriction uses only operation shapes, so it does not copy the world's history for each branch check. Custom context validators retain isolated complete inputs. Canonical candidate presentation uses the same fully validated derived step that will be committed; it does not settle that step a second time merely to construct its presentation. Full history replay remains part of validation.

History validation retains at most eight successful complete native-state hashes per fixed core registry. Only an identical state under that same registry can reuse a validation; any changed value, newly registered package, or custom rule implementation requires replay. Structural validation still runs. Explicit replay always executes the complete log, and restarting drops the memory cache. Engine snapshot handoff separately verifies the isolated copy against the original snapshot's hash and registry identity before consuming its one-use proof.

The creation wire format binds each parameter beside its declaration. Entity values have the exact canonical entity domain, and admission separately requires the actual action owner and pre-authored utterance. The compiler lowers this representation to independent immutable declarations and execution bindings; placeholder words are not accepted as entity IDs.

World effect references are checked in branch order during compilation. An entity may be created and referenced by a later effect in the same branch. An absent record binds the owning collection's version, while existing records retain atomic reads and known holders retain their versioned absent quantity slots. The committer rejects stale absence evidence and applies all effects atomically. Creation cannot author dynamic Agent model profiles; materialization assigns the pinned world capability profiles, and instance overrides continue to apply at invocation time.

Compilation closes nested predicate sources and expression reads into the program declaration before admission. It does not invent missing facts or rule authority. Every added source still must exist in the supplied catalog. World decision batches carry shared sources once, with each question binding its own source IDs, instead of repeating the complete mechanics catalog for every question.

Timing selects an authored temporal profile. Code derives fixed durations, travel rates, staged durations and open-ended checkpoints. Explicit quantities and durations must match evidence extracted from the action text. Each effect judgment sees its actual temporal plan and reads the selected profile version. An open-ended checkpoint retains the original attempt and active resource claims, increments a persisted checkpoint count and schedules its next authored boundary. A succeeded branch must require the explicit timing completion predicate to be true. A partial checkpoint produces a continuing receipt; it does not end the private instruction or satisfy a goal. Relevant observations still wake the owner, while repeated bare checkpoints do not add duplicate private action history or trigger receipt polling. World judgments reuse unchanged actual dependencies. Controller revocation releases interruptible reservations, and restart retains the original start, claims and next boundary.

Explicit quantity evidence uses a finite Arabic, Chinese or English number grammar. English cardinals and decimal digits remain exact quotations of the attempted action; the parser rejects partial number phrases and numbers embedded in identifiers. Model-provided numeric values cannot substitute for written evidence.

Compilation supplies code-extracted exact number quotations from the intent and utterance. Repair feedback includes the rejected quotation, its parse and the available exact quotes, without admitting classifiers as numbers. Expressions in JSON templates require an explicit `$expression` wrapper; unwrapped expression objects are rejected during admission with a targeted diagnostic.

The compiler sends each canonical collection once; atomic read keys address those records. An authored fact source aliases a current fact only while their values match; otherwise the original source is supplied separately. Repeated JSON-schema definitions use references. Stable world context precedes the attempt in the request layout. These are lossless layout choices, not removals of world evidence.

## Decisions and commits

Each semantic condition and candidate branch effect has a concrete yes/no/unknown question. Independent questions share one authorized world batch. Every batch includes its interaction partners, physical participant/containment envelope, and world laws. Mechanical expressions execute in code. Oversized inseparable questions use the gateway's explicit context fallback.

The native gateway preserves raw probabilities. Observed hundredth-precision Jev responses can sum to 0.99; validation allows only the corresponding bounded rounding interval (at most 0.02), while requiring complete domains, finite probabilities, and a maximal-probability choice. It does not renormalize distributions or use them for world randomness.

`WorldEventCandidate` binds programs, attempts, selected branches, materialized effects, deliveries, clock boundaries, random commitments, read versions/hashes, and full decision evidence. A selected branch must have all its conditions satisfied and its exact effects authorized. Missing or ambiguous branches remain uncommitted. Recorded answers must match the gateway's normalized output hash; changing an answer cannot reuse the original audit.

`commitWorldEvent` checks the earliest pending boundary, source hashes, actual read versions, canonical parameter ownership, decision bindings, causal assertions, references, write declarations, and quantity laws. It uses an isolated clone, so a later invalid operation rolls back the entire component. Physical time advances positively. `CommitReceipt` binds actual writes, events, and program receipts. Repeating a candidate with its durable receipt does not apply effects again. Identical no-op effects do not count as program progress.

World outcomes and private acknowledgements are distinct. An `attempted` acknowledgement confirms execution without disclosing an unobserved hit, failure or delivery. An `observed-outcome` acknowledgement requires a committed observation to the actor that establishes the exact outcome, checked by its source-bound effect judgment. Program progress uses changes visible in the actor's own perspective or deliveries to that actor; hidden canonical changes do not leak through its progress bit.

Random declarations bind exact authored distributions, purposes and complete branch stakes. `prepareWorldRandomPlan` freezes these inputs without extracting any RNG word or revealing the seed to the model. Jev must authorize applicability and stakes before code samples the seeded distribution. A separate control commit persists the reservation and consumes its RNG words before any model receives the result. Physical settlement then uses that immutable reservation; transport failure and restart cannot revise its stakes or refund its draw. The reservation locks its pending frontier until settlement. Unknown authorization does not draw. Model probabilities never enter this calculation.

Result resources are read-only. Replay reconstructs the original pre-draw revision, requests, actual reads and authorization, then checks the exact seeded result. The draw appears once in the canonical log. If later semantic judgments cannot establish a unique branch, the reserved joint frontier settles with blocked receipts and no invented effects; the draw remains consumed and the private program follows its declared recovery route. Physical time still advances to the attempted action's boundary. Such a receipt is not evidence of success, failure of an unobserved effect, or a completed goal.

Canonical timers, authored recurring condition impacts and condition expiry are hard time barriers even if the calling scheduler supplies a later boundary. Due timers fire or cancel according to their code-evaluated assertions; only firing timers wake their declared subjects. A timer or condition boundary commits without model work. Conditions persist their next impact time; code applies due impacts in stable time/identity order, clamps against the evolving meter state, advances each cadence and removes expired conditions. Action effects at the boundary apply before condition effects, so a completed cure can prevent that boundary's impact. Otherwise an impact due exactly at expiry applies before expiry removal. The candidate and committed operations retain these code-derived effects separately from model-authorized branches, and even fully clamped impacts bind the meter they read. An empty event cannot advance time without an actual due boundary. Replay and restart retain the same next due time. World event judgments also see authored timers.

## Local scheduling

`EventScheduler` retains a canonical pending queue and completed identities. An unresolved earlier event prevents acknowledging a later one. Owner-specific subscriptions wake only on relevant resource versions, receipts, or deadlines. Replaced subscriptions cancel superseded deadlines. Evaluation fingerprints detect repeated input/frontier without committed progress, including cycles through other frontier states and restart.

`worldProgramComponents` derives actual reads and possible branch writes from trusted mechanics and direct operations, adds declared dependencies and delivery recipients, and connects them through `jointActionComponents`. Collection dependencies overlap their atomic records. Independent component questions share a batch while the complete input fits. Partitions retain every interaction partner of their questions and omit unrelated components. Independent batches prepare concurrently with deterministic invocation and evidence ordering; canonical validation reconstructs the same participants. The earliest frontier settles atomically and the queue retains commit order.

DecisionEventState v6 retains canonical program activity reservations separately from private intention programs. Jev judges the temporal profile and completeness of shared claims against authored rules before an activity starts. Code derives per-actor claims from the profile and shared claim amounts from the facility contract. It checks capacity, respects queues, rejects when required by the facility policy, and asks for a priority choice only for actual contention under an adjudicate policy. Unknown priority leaves work queued. Existing active holders cannot be displaced by a priority answer.

Queued work has no start time or completion deadline. Capacity release starts it at the current canonical instant and derives a fresh completion boundary. Cancellation and completed attempts release their claims. Reservations, admission evidence, scheduled boundaries and queued instructions survive restart. The committer replays the same deterministic admission procedure from the prepared input and exact recorded decisions. Trusted Inspector displays the reservation history; Agent prompts never receive another Agent's private program. The native reservation journal is stored in execution state, not the baseline Activity table.

Private control restores checksummed libraries, program journals, receipts and pending attempts. Local wakeups run goal selection and program predicates through Jev; only new programs and concrete utterances call creation. Independent owners run concurrently with separate invocation ordinals, and all in-flight outcomes settle before failure propagates. A pending issued attempt is not issued again on restart. World rules can reuse the same private definition/node/parameter binding with a new `utterance` parameter, without regenerating the rule. Preparation preserves failed attempts for a relevant dependency change.

Failed world judgments retain the complete actual read union, bound source hashes and judgment evidence identities. Unknown conditions whose policy is wait remain suspended until one of those inputs changes. Rejected effect interpretations bypass the rejected library entry and receive one targeted creation revision. The revision budget binds the input before revision, so changing a generated read declaration cannot reset it. Structural repair exhaustion waits on the complete compiler input. Unrelated world mutations do not wake a semantic wait.

## Simulation entry and recovery

`DecisionEventAlgorithm` pins the creation, decision and context-fallback profiles, registry snapshot, program definitions and dependency-round limit in the instance's execution state. Bootstrap v4 covers actual private goals, compiles their issued first world frontier and replays resource admission before initialization completes. It preserves the initial physical state, time and RNG. Each new world library entry requires its actual creation audit and authored source hashes. Execution coverage binds goal coverage to concrete compiled, scheduled, queued or failed attempts; a private definition alone cannot establish executable coverage. A control commit advances the revision only; a physical event also advances the world step and strictly positive elapsed time. A quiescent world raises a typed waiting result instead of minting repeated empty revisions.

World and Agent profiles each bind `decision`, `creation` and the explicit context `fallback`. The default producer inherits those script bindings. An experiment may override any capability at instance creation; null retains the individual script binding. DecisionEventState v6 retains these overrides and Bootstrap v4 binds the complete producer reference. Commit validation checks world and owner-specific audit profiles against this pinned configuration, including after restart and cognition for newly created Agents. Arrival content uses the subject's creation profile.

The native bootstrap retains the complete model catalog configuration, including unused creation or fallback profiles. It contains credential environment variable names only. Recorded algorithm replay restores this exact catalog and pinned registry identity and derives invocation identities with the live gateway's function; it never contacts model providers. Sorted source catalogs keep compilation hashes stable when the Ledger serializes object keys canonically.

The fixed committer re-executes newly appended private instructions against the owner's actual resources. Generated definitions are re-admitted, creation output hashes are checked, semantic decisions are reconstructed from concrete frontier tickets, and issued attempts must match their private program or authorized player submission. Reusing an existing immutable plan rechecks today's source identity and reference catalogs; unrelated additions to the admission environment do not invalidate its original creation evidence. Persistent goal questions include the original goal, even when a generated mechanical condition is true. Completion checks run before replacing an ended program.

Player text remains an attempted action. Creation renders exact spoken content before world adjudication; canonical delivery establishes who actually heard it. A controller change interrupts private planning and revokes unstarted or interruptible pending work. Noninterruptible work retains its already established execution boundary. Resuming model control creates a local wakeup.

World settlement consumes exactly the persisted pending frontier. Private deadline queue items must come from the active interpreter. Canonical event evidence, actual observations, belief revisions and program receipts are replayed by the same deterministic implementation used for preparation and commit. Native history has source-bound decision evidence; it does not invent a legacy `causal-verifier` invocation.

Native history encodes prepared and settled control as lossless JSON deltas, each binding its exact base and reconstructed result hashes. Unchanged libraries, old cache entries and prior private journals are retained in the source checkpoint instead of copied into each step. The world authority is referenced by its pinned bootstrap hash; the step's execution-state envelope contains the resulting control hash. Replay and Inspector reconstruct the complete proof before using it. Delta decoding does not replace source-bound semantic validation, and the latest instance checkpoint retains complete live control for restart.

## Observation and cognition

A private frontier with no available instruction or outstanding issued attempt receives a source-bound wait assessment. Jev can retain a justified wait, preserve an unknown assessment, or request a plan revision when the owner still needs to contribute or gather evidence. Revision interrupts the program without changing its unknown predicates into false or producing world effects. The existing input-bound planning budget allows one targeted revision. Exact frontier and private-input reuse is cached; an unchanged wait creates no polling loop. Commit validation reconstructs the assessment before accepting its interruption, and rejects an arbitrary interruption without a controller change or reproducible issue failure.

Wait assessment receives the complete program, present condition verdicts and actual issue/receipt chronology. Repeated predicate proofs and their hashes remain in the local journal rather than being repeated in the semantic question. The private mechanics projection declares its quantity list complete for the owner's current quantity holdings; this does not establish historical transfers, another owner's inventory, or the absence of carried entities represented by containment.

`projectEventPerception` requires matching candidate and committed receipt hashes. Only explicit committed deliveries become observation packets. A known private speaker alias can be reused; an unidentified speaker receives a neutral local alias without canonical names or hidden identity claims. Hearing testimony adds evidence that words were heard and does not assert that their contents are true.

`reviseEventBeliefs` asks independent questions about the owner's existing claims using only that owner's authorized perspective. Supported and contradicted answers update stance; insufficient or irrelevant evidence leaves the claim unchanged. The same batch includes a gate for a useful new claim, commitment, report or hypothesis. A needed answer invokes creation with the owner's exact local entity and evidence domains, one targeted repair, duplicate checks and a required newly delivered evidence reference. Jev then judges each admitted proposal as supported, contradicted, unknown or discard; an unknown proposal remains suspected. New claims use a neutral 0.5 epistemic prior. Class probabilities stay in the decision audit. Failed creation preserves the actual observation and records a recoverable belief failure without fabricating a claim.

BeliefRevision v2 binds both decision rounds, optional creation, source-bound prompt identity and the resulting patch. Canonical validation requires the recorded decision uses and physical creation audits. `applyEventBeliefs` reconstructs the exact private input, candidate domains and judgments and derives the patch again during commit or replay. New evidence remains available directly to program predicates even without a new claim. Hearing testimony establishes that words were heard; neither creation nor belief inference changes canonical facts or completes a goal.

## Verification boundary

Tests exercise the actual ModelGateway with only HTTP replaced, compilation/repair, quantity transfers, stale reads, unrelated updates, source/evidence tampering, unknown, atomic competition failure, exact speech, no-op progress, and scheduler restart. SimulationEngine tests also cover registered execution, natural-language player actions, actual speech delivery, same-time control commits, controller interruption, quiescence, persistent replay and recovery without repeated effects. A real-model diagnostic is available as `scripts/experiments/jev-world-smoke.ts`, consuming a successful private-program probe. It exercises the world kernel directly, not WorldHost persistence or a complete game.

WorldHost lifecycle integration and the local Inspector expose native programs, coverage, wake reasons, decisions and measured call costs. World v15, SimulationState v17 and instance v24 persist the native contracts. Full A/B/C qualification is tracked in the spec evidence. Passing the runtime checks does not establish the acceptance targets.

## Joint quantity recovery

The kernel projects the complete authorized effect sequence on a transaction clone before admitting an event. A joint quantity overdraw retains the entire connected component for one input-bound program revision, with no partial world effects or deliveries. If a random draw has already fixed the stakes, an overdraw settles that reservation with blocked receipts and no effects; it cannot trigger a revised stake or another draw.
