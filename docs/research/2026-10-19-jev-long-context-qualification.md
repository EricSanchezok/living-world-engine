# JEV 长上下文接入与裁定耗时对照

本记录区分传输能力与游戏质量。长上下文接入和预算选择可以工作，但这批真实请求未通过语义验收，因此默认游戏配置不启用它，也不替换回复发布校验。实现契约见 [Spec 0208](../specs/0208-demand-driven-jev-long-context.md)，运行时机制见 [模型网关](../game-design/model-gateway.md)。

## 协议与证据范围

来源是凡人剧本的两个真实玩家回合，实例 `730d7ed8-e627-4107-abab-36bcc46c26e2`，世界哈希 `sha256:26142d110076bf522db42967d091e443f56b5819dc40d67169a28bd131f49710`。源报告固定的生产者为提交 `69885c705395b70c15882f251e69577c54a3a83c` 加工作区 diff 哈希 `91352d2115295dff2c2c301bb5072d673eed4940d4f9d9c5018a26ab08477605`，执行算法为 `direct-world@20`。原始 Ledger 位于 Git 忽略的 `.livingworld-cache/npc-efficiency/fair/`；本次结果位于 `.livingworld-cache/jev-long-context/full-live/`，包括完整来源、逐次请求、原始 HTTP、选定模式、用量、答案和差异。比较驱动为同目录上一级的 `compare.ts`。

从 Ledger 取出全部 17 个世界裁定和 12 个发布校验请求，通过可逆 codec 恢复原题，保持共享状态、问题、候选答案、世界版本和提示词不变。经当前真实网关提交给固定的 `jev-1.13.0`；实验目录显式声明长上下文能力。对照是已保存的 `deepseek-flash`、low 推理结果，不重新生成或改写旧结果。本次对照禁用 Flash 回退，以免把回退结果算作 JEV 能力；本地预算拒绝也保留在总样本中。没有修改玩家存档或规范世界状态。

耗时取每次实际 transport 的 `executionMs`，不使用延迟写入的事件时间戳推算关键路径。原始调用可能重叠，合计耗时不能作为玩家整轮等待时间。token 取供应商实际 usage，不把本地估算或压缩比例当计费数量。两供应商 tokenizer、问题布局和输出协议不同，token 数不是统一工作量单位。

## 配对结果

| 请求类型 | JEV 成功执行 / 全部 | 原 Flash 耗时合计 | JEV 耗时合计 | 原 Flash 输入 / 输出 token | JEV 输入 / 输出 token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 世界裁定，可配对成功请求 | 16 / 17 | 928.676 秒 | 14.751 秒 | 921,843 / 165,752 | 1,420,805 / 80,287 |
| 回复发布校验 | 12 / 12 | 269.104 秒 | 4.429 秒 | 133,425 / 45,620 | 177,416 / 3,830 |

世界裁定成功样本平均从 58.0 秒降到 0.92 秒，发布校验平均从 22.4 秒降到 0.37 秒。这是请求耗时对照，不是游戏提速验收。世界输入 token 增加约 54%，发布输入增加约 33%；JEV 的价格与输出计费方式不同，不能据此声称总费用同比例增加或减少。[TypeSafe 官方模型说明](https://docs.typesafe.ai/models)列出的输入价格为每百万 token 0.042 美元、输出免费，据此该主批次已知用量约 0.0671 美元；这是估算，不是账单，也不包含开发探针。

第 17 个世界请求（源 Ledger sequence 896）完整原生请求约 950 KB，本地输入估算 574,398 token，超过 262,000 上限，在 HTTP 前拒绝。它没有 JEV 实际 usage，不能按成功样本外推其速度或成本。原 Flash 该请求为 83.072 秒，仍保留在完整基线中。

这个请求只有两个动作，却包含 628 个问题；其中 550 个来自遍历全剧本资源的消耗和产出规则，每条分别询问是否适用与数量。共享状态约 171 KB，问题部分约 739 KB。部分属性的有限值选择涵盖 805 个候选，并分成多个条件子题。这说明扩大上下文不能代替问题构造优化：大批重复或无关候选仍然耗时，也增加误判机会。问题生成的直接来源为 [world.ts](../../src/engine/direct/world.ts) 的资源规则循环与 [有限值分组](../../src/engine/direct/property-value-choices.ts)。

## 语义审查

16 个成功的世界请求共 573 个问题，原始选项有 314 处差异。这个数字不是错误率：例如 `planned` 与 `s60` 可以表示同样的六十秒，`hidden` 与 `unknown` 在部分调用点都不发布信息。质量判断需要返回源事实和提交含义。

发现的明确问题包括：

- 人物回家不应改变房屋的道路关系。源 sequence 115 的 `a0_fact0`、`a0_fact1` 分别询问林家小院通往北坡和药院的 `route-to` 属性；JEV 均把目标改为林家小院自身。相同错误在后续对应请求中重复，不能归因于合理的叙事差异。
- 同地普通说话的旁听被判为未送达或不确定。源 sequence 107 的交谈具有相同地点且没有耳聋、隔墙、耳语等阻隔，既有听觉规则也明确旁听者无需是被称呼的人。漏送达会减少 NPC 可用证据及后续自然反应。
- 发布校验放过了无依据的表达。sequence 205 的“压低了声音”没有对应 manner；sequence 711 增加玩家“回身”；sequence 1028、1108 将未获得新观察的药材检验和未付款状态写成当前确定事实。JEV 在这些相关轴上选择了通过。它们不适合作为发布拦截能力的合格证据。

首个世界样本完整调用标识为 `dd588ae0-f081-4db2-bd7c-d78216fe3ad3::rt:model-audit:1f978080a4d1bb8e39e44e71683bc52392066023e9c58dad7451084c13a0e8d3`，来源事件区间 89–110；首次道路误改的源调用为 `dd588ae0-f081-4db2-bd7c-d78216fe3ad3::rt:model-audit:fdef726622e639e75f7b25c28b6cc78d38a43be894bdb152c4ff93a63c4680ad`。首次异常边界在原生语义答案，早于内核提交。schema 合法不能证明属性改变有因果依据。

补充开发探针分别比较三个原请求的固定 `jev-1.14.0`，以及把已有裁定规则和对应动作就近展开、保留完整共享状态的 `jev-1.13.0`。道路误改仍出现，后者还产生额外可见性与属性误判。两个版本和问题展开结果均不构成激活理由，未进入生产配置。最初一版展开超过预算，没有发送 HTTP；该失败另保留于 `direct-113/`，成功执行的后续版本保留于 `direct-113-r2/`。开发样本没有从主批次中挑选替换成功项。

[JEV 1.13 官方能力边界](https://docs.typesafe.ai/model-jaggedness/jev-1.13)说明多层引用、无关大状态和精确数字任务容易降低准确度。它与本次现象一致，但不能单靠这份说明判定具体根因；当前证据只支持“完整大状态下的现有问题结构尚未合格”。

## 裁定与发布的优化顺序

以下是待验证方案，不是本次已经获得的速度收益。

1. **先改善裁定输入的相关性与问题边界。** 首个请求的共享状态约 164 KB，其中 373 条剧本规则约 123 KB。动作和相关人物并不多；主要开销不是唤醒了全部 852 名角色。优先处理全资源规则遍历，为规则建立剧本声明的适用范围与可验证依赖，把全局规则和本次必要规则清晰区分；未知适用性保留，完整声明仍进入证据。先减少题目查找层次、让属性所属主体和因果问题明确，再验证范围过滤。有限值子题还必须携带自己的完整判断依据：JEV 并行回答，不能要求一题读取同批另一题尚未生成的答案；路径选择与一致性应由代码组合。不能用简单关键词截断、固定条数或删除远处重要规则换速度。
2. **复用没有变化的裁定依据。** 在现有依赖版本机制中，按动作、相关事实、规则和认知版本判断哪些答案已经失效。新增一个无关事件不应全量重算；动作目标、观察者位置、时长或规则变化必须失效。先从原始追踪统计可省的重算，再改失效键，不新增模型裁判或每次二次核验。
3. **减少旁白返工，再优化发布校验分工。** 当前已有纯已知对白直出、精确引用检查、同批多个语义问题、生成与校验重叠；这些不是待新增的优化。应先让生成材料明确哪些内容可表达、哪些只有旧证据，并只重写被拒片段。固定引用、身份、数量与可确定的时间换算由代码校验；语义因果、角色自主权和隐含知识仍需要模型判断，不能删除这道门。
4. **用带明确正反例的发布样本决定模型替换。** 本轮 12 次发布校验不足以证明 JEV 可替换 Flash。应覆盖虚构动作、错误时间、越权知识和自然但合法的表达，分别测漏拦截与误拒绝。只有相应任务通过验收才整体切换该任务，不采用每次 JEV 后再让 Flash 全量核验的双重开销。

整体验收还需独立真实游戏回合：规范事实、话语实际送达、重要记忆、合理耗时和玩家获得的信息都要核对。原始请求回放只能说明这些固定输入的表现，不能证明分歧后的故事仍自然或完成率不下降。

## 接入验收与交付边界

`check:fast` 通过：413 个测试文件、2,846 项测试，以及 Lint、类型、提示词资产、算法、世界样本和治理检查。最终代码另通过上下文预算、原生传输、决策回退和供应商矩阵共 44 项针对性回归；覆盖默认与长上下文并发、真实超限后的单次升级、长上下文失败回退、完整请求保留和发布策略计量。

用户在查看质量结果后明确选择先交付接入和对比报告、保留现有游戏裁定质量。因此本次没有启用默认剧本的长上下文配置，没有替换发布校验模型，也没有以这批不合格答案推进玩家存档。后续的裁定输入优化与整局验收属于下一项工作。
