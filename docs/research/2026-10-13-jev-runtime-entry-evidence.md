# Jev 程序引擎：实例入口与真实调用记录

## 状态

这是开发联调记录，**不是三臂性能验收**。当前新执行器可以通过 SimulationEngine 与 WorldHost 提交和重放；默认算法、最终契约版本和完整任务确认仍在实施中。架构契约见 [Spec 0181](../specs/0181-jev-decision-event-engine.md)。

## 已验证入口

- 原生 decision-event 执行器通过同一个 CanonicalCommitter 提交，判断证据绑定原始条件、候选效果、授权视角和实际读集。
- 私有程序在 SQLite 实例中保存，关闭数据库、重新打开和规范重放不会再调用模型或重复传播对白。
- 没有事件时运行进入等待，世界时间、物理步骤数和规范 revision 不增加。
- 程序终止与长期目标完成分别验证；结束一条询问程序没有把守卫的长期目标标为完成。
- 玩家自然语言和预先生成的对白经过实际传播，成为另一角色的观察。
- 完整入口检查曾通过 350 个测试文件、2,131 项测试；后续的程序复用、扩展和 Inspector 改动另外执行检查。

测试入口为 [原生运行时测试](../../src/engine/events/__tests__/runtime.test.ts) 和 [持久化实例测试](../../src/server/__tests__/decision-world-host.test.ts)。这些自动化检查替换远程 HTTP，保留模型网关、程序生成契约、裁决和持久化实现。

## 空间站真实联调

[空间站剧本](../../test/fixtures/station-program-world/script.yaml) 包含维修工程师、军需官、独立检查员三个角色，设有资源守恒、维修耗材、私人校验码、压力测试随机分布和 120 秒截止时间。它是新增的通用性场景，不能替代完整 49 主体任务。

2026-10-13 的一次开发运行使用真实 Jev 和 DeepSeek，经过 WorldHost 创建观察者实例并执行一个物理边界。世界时间推进到 1 秒。军需官实际向工程师传达了“两个能量电池交换一个密封组件”的条款；本步没有转移资源，没有宣布交易或维修完成。提交状态的规范重放一致。

检查员的规则生成失败：初次响应不是有效 JSON，唯一一次修复将 `unknown` 错误放入两个 predicate 的 `test` 内。失败保留在程序运行状态中。随后补充了具体字段位置提示。该提示的效果尚需新运行验证，不把这次失败记作成功恢复。

这次运行新增 **16 次 HTTP 请求**。累计实施期 40 次，加上设计阶段的 89 次，共 **129 次真实请求**。实施期峰时价格估算 6.172142304 元；设计期按固定预算换算计 0.285838512 元；累计约 **6.458 元**。价格和保守换算仅用于 100 元累计上限，非账单或实时汇率。原始请求、响应、失败与 SQLite 记录留在 Git 忽略的本地实验目录，密钥不进入记录。

## 第二次开发运行

第二次运行申请三个物理边界，实际只到达 120 秒截止事件，随后停为 waiting-for-event；没有完成三个边界，也没有完成任务。规范重放一致。本轮新增 13 次请求，累计实施期 53 次、含设计期 142 次；累计峰时估算约 6.633 元。

从持久化程序和判断记录定位到两个具体问题：工程师的启动谓词同时出现在 interrupts，导致程序刚启动便中断；军需官的位置判断只声明了实体记录，没有包含私有位置关系，Jev 因证据不足正确返回 unknown。检查员还出现节点共享与谓词字段结构错误。它们是未完成样本，后续通过准入检查、完整授权证据和具体修复提示处理。

针对这些样本，准入现在拒绝同时用于启动和中断的谓词，结构错误会指出具体节点。语义判断自动绑定角色自己的位置、事实、观察与认知证据；这些输入同时参与缓存失效与唤醒订阅。实际谓词中断会撤销可中断的待执行尝试，并进入有次数限制的计划修订。回归检查覆盖证据变化导致旧判断失效、中断后不再执行旧尝试，以及修订队列。真实任务效果仍需重新运行验证。

## 解释限制

第三次开发运行先完成三个讲话边界，随后关闭数据库、重新打开并继续运行，最终在 121 秒进入等待。两段规范重放均一致，但资源未交换、泵仍泄漏且未测试，所以任务仍未完成。真实证据暴露了一个重复判断问题：军需官对同一个接受条款谓词、同一个输入，先在里程碑判断得到 yes，紧接着进入流程分支时又被问了一次并得到 unknown。运行时随后加入谓词级的持久证据复用；按原请求实际读集和问题版本失效，流程复用不新增物理请求。该修复有重启、流程和规范重放回归检查，真实效果仍待新实例验证。

一个成功物理边界不能证明任务成功率、80% Jev 请求占比、80% DeepSeek 请求降幅、70% 费用降幅或 50% 等待改善。当前没有产生这些比率。后续需要冻结任务、来源、模型配置和代码版本，分别计量冷启动、首次生成和稳定执行；A/B/C 的失败、预算停止和删失都必须保留。
