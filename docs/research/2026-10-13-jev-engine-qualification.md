# Jev 引擎三臂验收协议与证据

本文是验收记录。实现细节见 [程序运行时](../game-design/world-program-runtime.md)，已有开发探针见 [真实入口证据](2026-10-13-jev-runtime-entry-evidence.md)。正式协议由 [qualification protocol](../../scripts/experiments/jev-qualification-protocol.ts) 固定，执行入口为 [qualification runner](../../scripts/experiments/jev-qualification.ts)。

## 协议

A 使用独立冻结的旧引擎 checkout；B 使用新架构及 DeepSeek 决策；C 使用新架构及 Jev 决策。B、C 的创作和上下文超限回退都使用关闭 thinking 的 DeepSeek。每个 worker 从对应 checkout 加载 loader、模型网关、提示词、WorldHost 和重放器；A 的提示词搜索工作目录固定在 A 的 checkout。所有调用共用一个累计预算账本，包含先前的规划和开发调用。

三个 canary 分别使用原 E3 的问询、观察、交易任务，首臂依次轮换为 A、B、C。确认集保留六类任务、每类五个独立种子、每个任务三次原始自然语言输入。每个样本保留全部 48 个自主角色及一个玩家。相同的有限工作与短检查点世界配方在各生产者中独立执行；模型能力字段、契约版本、核心规则包生产者版本和显式条件周期之外的剧本内容必须具有相同哈希。条件周期另行固定在 manifest；新契约中的 burning 周期为 60 秒，旧引擎没有对应字段。这是被比较架构的时间语义差异；涉及该条件的样本需单独审查，不能声称时间语义完全相同。

各臂独立完成初始化、初始程序生成及玩家到达，不交换 bootstrap、程序或推理结果。冷启动、首次输入和后续输入分别记录墙钟时间和账本差额。每次输入最多允许六次提交及 600 秒新增调用时间；已发出的调用继续收集用量。修复、拒绝结果和回退调用都计入费用及调用数量。

输入经过真实 WorldHost 提交，保留 SQLite、完整初始和最终文档、每次输入的响应及观察、运行终止状态和累计用量。认知提交只增加 revision；物理事件要求 step 加一且世界时间严格增加。逐次检查连续提交和重放一致性，最终重放不得调用模型。

## 结果解释

运行终止、程序结束和长期任务成功分别处理。有来源的非空观察仅标记为候选反馈；只有独立核对持久化事实、实际传播和任务禁止项后，才可以标记为有用反馈。未执行、失败、超时和预算删失样本保留在原始样本集合中；未完成的 A 样本不产生成功任务费用比或虚构提速比例。

[汇总工具](../../scripts/experiments/jev-qualification-report.ts) 从同一预算链的请求序号区间统计实际 Jev、DeepSeek、其他请求及费用，包含修复与被拒绝输出，避免重复使用样本标签导致跨批次混计。语义审查绑定完整结果哈希、持久化证据引用和具体反馈 revision；没有实际送达观察的响应不能计为有用反馈。缺少审查、未执行样本、未结算调用及不完整确认集均不会通过验收。成功任务费用包含该臂冷启动；未能记录的冷启动精确耗时保持空值。当前汇总只在 A、C 所有任务成功且每次输入都有审查确认的有效反馈时给出费用和时延降幅，避免删失样本产生虚假比例。

首批冻结于 `b21729ed` 的三个 canary 组共九臂均在模型注册表预检阶段终止：未参与实验的 Kimi provider 元数据缺失导致整个全量目录不能捕获。没有新增付费 HTTP 请求，九臂的 27 次输入均未执行；这些是基础设施失败，不能作为任务完成率或模型质量证据。驱动将实际所需的原始 profile 和 account 原样投影到独立目录，以排除无关 provider 的可用性影响；修复后使用新证据批次。目标完成率、Jev 占比、费用和反馈等待时间的目标保持未验证。

第二批的 B/C 引擎冻结于 `c4ed0a37`。第一组 A、B 均创建了完整 49 主体，玩家到达后 revision 为 1、step 为 0、历史为空；驱动错误地要求 revision 为 0，因此没有提交玩家输入。暂停后续样本后，只修正测量与行政恢复代码，保留两个实例及原始失败记录，允许通过 `--resume-arrivals` 继续相同输入。恢复不重复初始化、不改引擎生产者或模型输出；原驱动未保存的冷启动精确耗时标记为不可用，已发生费用全部保留。该修复用独立驱动提交记录，不将测量错误伪装成任务结果。

恢复后的第一组 A 首次输入耗时 372.64 秒、费用约 18.397991712 元，因 `observation for lord-maracan contains protected information` 被拒绝；没有规范提交或玩家反馈。第二次输入启动后，为给新引擎及工作台检查保留累计预算，停止新增调用并收齐在途用量，新增约 1.630776096 元；该输入记为删失，第三次未执行。A 的最终状态仍可零模型调用重放，Ledger 无孤立记录或索引缺失。该失败基线不产生速度或成功任务费用比。

第一组 B 的三个输入分别用时约 289.57、269.80、331.25 秒，费用约 4.454053536、4.771603392、3.471302880 元。第一个输入因资源声明判断为 unknown 等待证据，只提交了同一时刻的控制记录；后两个输入因持续活动缺少完成条件被内核拒绝。最终 revision 为 2、世界时间为零，三个输入均无玩家观察，重放一致且无新增模型调用。这个样本没有任务完成或有效反馈证据；@7 的后续编译期修复见 [postmortem 0151](../postmortems/0151-world-branch-completion-checked-too-late.md)，冻结样本仍使用原来的 @4 生产者。

第一组 C 的冷启动耗时约 408.59 秒，287 次 HTTP 请求，费用约 5.671796688 元。第一次输入执行约 607.40 秒，79 次请求，费用约 5.459722416 元；发生两个同一时刻的控制提交后，同样因持续活动缺少完成条件被拒绝，新增调用时间也到达限制。最终 revision 为 3、世界时间为零，没有玩家观察；后两次输入未执行。最终状态可零模型调用重放，Ledger 没有孤立记录或索引缺失。

该 C 样本的运行期请求为 Jev 32 次、DeepSeek 47 次，Jev 占比约 40.5%，低于 80% 目标。它不代表稳定运行期或独立确认集。三个已记录臂都没有成功任务或有效反馈证据；冻结生产者发生执行失败后，停止后两组 canary，保留六个未执行臂。整个 canary 协议的 27 次输入中，实际执行六次，21 次未执行。确认集没有启动。汇总的 `completeEvidence`、`comparable` 和 `qualified` 均为 false；费用降幅、DeepSeek 请求降幅、中位反馈改善及 P95 比例保持空值。

## 累计预算与交付边界

本轮实现、开发联调及验收共记录 2,095 次 HTTP 请求尝试，加上规划期的 89 次，共 2,184 次。按固定保守价格及规划换算计算，已知用量估算为 79.784950080 元，另有三次连接中断保留最大费用预留 1.274848800 元，合计预算占用上界为 81.059798880 元，低于 100 元。三次未知用量没有被记为零费用；其中两次已审查并按完整预留隔离，最后一次仍阻止实验继续派发，所有在途请求均已结束。该金额是预算估算和未知费用上界，不是供应商账单。

decision-event@7 的真实开发状态、资源转移、完整世界启动失败及 HTTP 检查由 [入口证据](2026-10-13-jev-runtime-entry-evidence.md) 记录。后续实现不能改写 @4 的冻结结果。最新生产者仍需重新冻结并完成完整 canary、独立确认及语义审查；默认路径的代码实现不等于这些验收目标已通过，旧的显式参考执行链尚未退役。

## 运行方式

先提交已经检查的实现，然后执行 `npx tsx scripts/experiments/jev-qualification.ts --mode prepare --root <new-evidence-directory> --baseline-root <frozen-checkout> --budget-root <existing-cumulative-budget-directory> --cache-root <existing-local-retrieval-cache>`。该步骤不调用付费模型，固定生产者提交、模型目录、世界内容及协议。随后对同一证据目录分别执行 `--mode canary --root <evidence-directory>` 和 `--mode confirmation --root <evidence-directory>`。任何生产者或协议修改都要求新的证据目录；已有的部分样本不允许静默重抽。

全部付费 worker 关闭后，执行 `npx tsx scripts/experiments/jev-qualification-report.ts --root <evidence-directory> --phase canary --output <new-report-file>` 生成不可覆盖的汇总；确认集使用 `--phase confirmation`。独立语义审查以 `--reviews <review-json>` 输入，格式由 [审查契约](../../scripts/experiments/jev-qualification-analysis.ts) 定义。没有审查文件时仍输出实际费用与调用量，验收状态保持未通过。
