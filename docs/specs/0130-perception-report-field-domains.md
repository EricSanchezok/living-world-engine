# Perception Report Field Domains

Artifact-Version: 1
Status: Approved

## Intent

Under the [player-action efficiency experiment](0122-player-action-efficiency.md), test whether field-local reference domains and an explicit identity-denotation description reduce malformed provenance and part/whole binding mistakes. A global catalog's assertion permission does not authorize every output field. This experiment preserves the existing evidence boundary rather than accepting source actions as established world evidence.

## Contract

The benchmark adapter specializes only the generation schema for terminal perception reports. For evidence, check references, existing local claim identities and canonical introduction bindings, enumerate every catalog handle of the required kind with the permission used by the existing materializer. Identical domains share one schema definition referenced from each field, avoiding repeated long catalogs. Empty domains permit no existing value while preserving empty arrays, nullable bindings and proposal references wherever the original schema allows them. Keep all candidate data and ordering, all report fields, target cardinality and source context. Per-target branches compile exact assignment coverage and the existing fixed-check provenance predicate. A check must match the target observer and source action, carry a Fact or Law cause, and have a committed result; perceived reports may cite only successful checks and cannot omit all checks when that pair has committed uncertainty. Negative reports may cite failed checks or no check. Each branch copies its observer, source action, and the matching checks’ stakes and results beside the target index. No semantic relevance selection or observer inference is performed; all canonical checks remain authoritative.

The canonical introduction reference describes identity, not ownership, containment or a part/whole relationship. A local entity naming a distinct part cannot bind to its carrier solely because that carrier exists. Unbound local identities and evidence-supported new appearances remain possible; no rule bans introductions or forces existing identity reuse. This description clarifies the existing identity contract, but cannot mechanically prove a natural-language denotation.

The canonical request schema, preprocessing, check branch, generated example, model settings and all validators remain unchanged. The adapter changes only the terminal report generation schema and pins that transformation in the prompt version. It neither rewrites outputs nor filters invalid fields. Reject incomplete, duplicate or mismatched catalog membership and pre-existing wire adaptations rather than silently composing incompatible experiments. This is prompt-visible schema specialization in hosted JSON mode, not constrained token decoding.

## Plan

Freeze a same-source comparison at the complete committed-check continuation of the latest player failure, in B/C/C/B order with one new HTTP per trial and no continuation or repair dispatch. Both arms retain all subjects, actions, targets and world evidence. Preserve the historical root failure and first report as separate evidence; report schema admission, receipt admission and source semantics independently. This continuation comparison does not measure initial check selection or full-player latency. The earlier controlled-source protocol remains: freeze a comparison on the ten complete onset sources with alternating order. Both arms retain the complete law index and explicitly select the independently verified terminal-root-closer parser. The treatment alone adds field domains and the identity description. Preserve required check continuations, block repair requests before network dispatch and count their demand. Permit at most twenty primary calls and four required continuations. Quantify small-source and historical complete 49-Agent request size before paid dispatch. Any default integration requires separate source-semantic and full-player qualification; older failed prompt combinations remain evidence.

## Verification

Verify each domain equals the entire applicable source-catalog set and preserves literal opaque handles. Verify the source, canonical schema, check branch, example and every other physical request field remain identical. Exercise real gateway-to-Truth materialization for valid reports, invalid references, cross-observer identities, missing targets, justified fixed checks and ordinary repair. Verify shared checks remain available for each explicitly cited source action of the same observer, successful and failed commitments remain fixed, and checks cannot move to the reversed observer/action pair. Runtime diagnostics identify every invalid check citation by the original report ordinal and check ordinal before report sorting, with only mechanically usable replacement references; they never alter output. Preserve null bindings and new local proposals. Review every reason, stimulus, introduction and claim against complete sources after live trials. Run focused checks and check:fast before committing or paid dispatch.
