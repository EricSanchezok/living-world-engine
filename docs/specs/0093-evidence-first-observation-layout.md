# Evidence-first observation layout

Artifact-Version: 1
Status: Approved

## Intent

Test source-first observation generation without changing the available actions, perceptual evidence or output meaning. Continuing autonomous optimization authorization covers the opt-in experiment, not default promotion or semantic qualification.

## Contract

The source-bound observation candidate may select a hash-pinned evidence layout. Its physical JSON schema presents each observation's existing sourceEventRefs before introductions, apparentClaims and summary. Every original schema constraint and required field remains identical; only property order changes. No output field is added, omitted, filled or rewritten. The production Zod schema and materializer remain authoritative.

After the full original context, schema and repair evidence, repeat the registered observation contract and an exact per-slot copy of the existing observer binding and current events. Derive the binding from each reconstructed logical context and reject a conflicting outer binding. Single-observer requests use their own context. A repair receives its current exact slots and evidence, never the original root's unrelated slots. The appendix ends with the same evidence-type distinction and complete-field obligation. It does not infer access, occurrence or success from an action, outcome status, event count or reference membership.

The original system and user instructions, all contexts and reference domains, output values, batch capacities and repair limits are preserved. The appendix participates in input accounting, request evidence and prompt identity. Unsupported non-JSON-object transports reject it before dispatch. No extra model invocation, thinking, critic, semantic default or hard truncation is introduced. Default observation configuration stays unchanged.

## Plan

Implement the physical request layout below observation batching, register its optional identity, and validate exact source and schema preservation through the real coordinator and HTTP adapter. Freeze request hashes before bounded paid development diagnostics. Preserve previous failed outputs and do not treat repeatedly inspected development cases as held-out confirmation.

## Verification

Exercise single and shared requests, scoped repair, foreign owners, absent events, complete actions, conflicting bindings and unsupported schemas. Verify equal canonical schema hashes despite property order, unchanged output materialization, actual HTTP field order and postlude placement, and registered candidate routing. Run focused tests and check:fast before committing. Mechanical layout checks do not establish narrative entailment; paid evaluation separately examines each claim and its source.
