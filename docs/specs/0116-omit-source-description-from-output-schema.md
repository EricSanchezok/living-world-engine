# Omit source description from the output schema

Artifact-Version: 1
Status: Approved

## Intent

Test whether eliminating a redundant optional output field prevents source-description rewriting failures. The user's continuing autonomous efficiency experiment authorization covers this bounded representation candidate within the existing budget.

## Contract

A prospectively selected `original-action-omitted-v2` description policy excludes `temporalPlan.description` from every wire schema branch and instructs the model to generate only its temporal and dependency decisions. The existing immutable source action and physical slot binding restore absent descriptions exactly. Context, legal profiles, conditions, candidate scope, causal evidence, resource claims and recovery limits remain unchanged. Supplied contradictory descriptions are rejected with original response evidence; the engine never rewrites them into success.

The existing `original-action-v1` policy remains the frozen comparison arm. The new policy binds a distinct prompt and Composition identity, and does not change the default algorithm. Removal applies only to the source-owned Activity description, not authored profile descriptions, fact text, source actions or model-owned explanations. Restoration is not a semantic verdict about the selected timing or dependencies.

Targeted comparisons freeze source requests, model/price settings, order, repetition count and stop criteria before fresh responses. Report original wire validity, source consistency, complete compiler acceptance and semantic evidence separately. A first-response schema probe cannot establish complete gameplay or recovery savings. A qualified candidate still requires the full-world checks in the ongoing experiment contract.

## Plan

Expose the omission policy through the existing representation adapter and registry, binding its prompt and schema to an independent Composition. Preserve the default and frozen comparison policy. Validate the complete compiler path before freezing a bounded fresh-response comparison; only a measured qualified candidate proceeds to the existing full-world acceptance path.

## Verification

Exercise both policies through the real represented compiler, including all temporal branches, omitted fields, contradictory supplied fields, reordered repair slots and unrelated invalid fields. Preserve initial and repair source identity and verify unchanged canonical plans, activities and dependencies for equivalent decisions. Verify the registry pins the new policy and rejects a mismatched prompt. Capture actual gateway requests before paid comparison, with thinking disabled and complete source cardinality. Run relevant tests and `npm run check:fast` before committing.
