# Perception derived-source diagnostic

Artifact-Version: 1
Status: Approved

## Intent

Isolate the deterministic opposed-source dependency already used by the assessment experiment. An opposed Rating uniquely determines its numeric source; independently generating both introduces a contradiction without adding a semantic choice. This benchmark follows the delegated player-efficiency work and does not promote the failed combined assessment protocol.

## Contract

The optional transport omits only opposed difficulty.source and derives the canonical Rating source from the model-selected ratingRef. Environmental sources remain explicit. The observer, perceived target, opponent, both Rating selections, stakes, mode, visibility, causes and done decision remain model-owned. An extra opposed source field is rejected, never overwritten. Existing canonical reference, ownership, task, source-reuse and numeric validation still runs before RNG. Full state and assignments remain available, and initial, repair and continuation requests use the same transport contract. Source or request mutation invalidates decoding.

The shared decoder also serves the existing assessment experiment without changing its outputs. Default execution does not select this diagnostic. Canonical schema, saved checks and old evidence remain unchanged. Derivation is an explicit transport rule, not a correction of an invalid historical answer and not constrained decoding.

## Plan

Compare example omission alone with example omission plus this source derivation. Freeze two repetitions of the four existing visibility controls in alternating order, followed only after all eight treatment controls pass by three alternating pairs of the complete 49-Agent source. Maximum twenty-two new first-response HTTP calls; block and report repair and continuation demand before additional network calls. Retain all failures and do not restart terminal trials. Bind code, runner, complete source, model snapshot and every physical request before dispatch. Keep thinking disabled and all original model settings.

All three full treatment batches must pass original validation and source semantic review before integration is considered. The control gate is only a development screen. Done, mechanical acceptance and small-case latency do not establish player completion or near-zero repair. Count failures, usage, cache, latency and blocked follow-ups separately.

## Verification

Exercise the actual gateway and Truth Engine for clean, repaired and continued requests, distinct perceived object and opponent, null aptitude, environmental evidence, wrong owner, reused Rating, unknown references and extra source rejection. Compare exact canonical checks and RNG against the existing contract and verify source immutability. Run assessment regressions and check:fast before local commit and paid dispatch.
