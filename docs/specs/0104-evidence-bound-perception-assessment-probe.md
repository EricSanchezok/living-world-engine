# Evidence-bound onset perception assessment probe

Artifact-Version: 1
Status: Approved

## Intent

Under the user's continuing authorization to optimize non-thinking gameplay autonomously within the existing budget, test an explicit perception decision representation before integrating a new reaction basis. The production check-or-done protocol cannot carry the distinction between established visibility and absence of sensory access. A successful format check does not establish correct perception or preserve a reaction opportunity.

## Contract

This benchmark-only candidate retains the full source state, actions, assignments, reference catalog and generation settings. A single response covers each assigned observer/action pair exactly once with selected existing evidence, explicit current values for every selected Fact, and one of visible, no_route, check_required or insufficient_evidence. Check keys associate explicit checks with the pairs they assess; shared checks may support multiple actions for the same observer. Every requested check must be used and must cite the matching observer and source actions. Terminal assessments cannot carry checks. The engine verifies request-state binding, pair coverage, reference identity and current Fact equality; it never derives visibility from a fact name or rewrites a verdict to pass a test.

Evidence may cite supplied Actions as attempts, alongside state facts and laws; an action reference is never evidence that its intended effect already occurred. Each check names its perceivedEntityRef explicitly, distinct from the assessment's sourceActionRef and any opposed difficulty targetRef. The perceived-entity conversion renames this field to the production targetRef, preserves its explicit value including null, and rejects the ambiguous old field rather than interpreting an action as an entity. Each representation revision has a separate prospective freeze and terminal trial; stored earlier outputs are not reclassified.

The opposed numeric source is functionally determined by the model-selected target Rating under the existing numeric contract. The candidate asks for that Rating once and mechanically constructs the identical Rating source; a separate opposed source field is invalid. This removes a redundant symbolic selection without choosing an opponent, Rating, visibility or difficulty for the model. Environmental source selection remains explicit. The production materializer still verifies the chosen opponent owns the Rating and preserves the independently selected perceived entity.

Each assigned pair also has an adjacent work item with its unchanged source action, explicit source actor and observer, current onset clock, the observer's complete owned Rating choices, and both participants' complete current placement chains through the root. Each spatial row copies the existing entity's name, kind and description and binds the exact placement edge, including a null root; cycles or missing entities fail instead of yielding a partial chain. This is an additive index into the original complete context, not a replacement or sensory-access filter. Shared ancestor containers do not mechanically establish visibility, and different placements do not mechanically rule out supported remote channels. The proposed next temporal boundary remains uncommitted future context, not evidence of an accomplished action.

Check identity and question are determined by the explicit assessment-to-check associations. The model does not reselect a check actor, rewrite onset stakes, or repeat source Action causes: the codec constructs exactly the common observer, the fixed onset question at the bound source time, and the associated source actions. Shared checks remain legal only for the same observer. Each check explicitly selects one or more existing Fact/law basisRefs, also present in every associated assessment's evidence; these become its world causes without choosing or supplementing evidence. This represents the already assigned question rather than interpreting an omitted action meaning. Legacy actorRef, stakes and causes fields are rejected. It does not prove that a selected basis supports perception or that a selected Rating is appropriate.

The selection representation adds a request-local key with an explicit type prefix to each existing reference-catalog row and a task key to each existing work item; original fields and free text remain intact. Every current Fact row also displays its snapshotKey. A Fact key explicitly selects that complete displayed Fact and its current typed value at the bound source state, rather than asking the model to copy the value again. Before constructing a request, the codec verifies each displayed snapshot against the actual source Fact, including entity-valued references. Every Fact in the original candidate domain must have its value in the supplied state projection; a missing row stops preparation rather than exposing undisplayed state or narrowing the candidate domain. It restores values only for explicitly selected snapshots; it cannot choose evidence or infer visibility. The output uses evidenceKeys and rejects copied value objects or legacy evidence fields. Selecting a snapshot does not prove that the model understood its value or applied it correctly.

Its strict output object covers every task key exactly once. Typed key sets constrain entity, Rating, world-cause and environmental-source fields; basisKeys accepts only existing Fact/law choices. Evidence kind and source kind come only from the selected catalog entry. Shared check associations, request ordering, null perceived entities and all original semantic choices survive encoding and decoding. Unknown keys, wrong uses, duplicate evidence or task identities and changed source/request/snapshot bindings fail; the codec does not match names, repair old responses or add missing evidence. Context restoration removes only codec-owned annotations and must reproduce the complete original context exactly. Request manifests bind the symbol table, input state and physical request before dispatch. Reusable schema definitions prevent repeated task slots from expanding identical key lists. Synthetic schema examples are omitted so generated placeholders cannot substitute for the actual task and evidence. This is representation validation, not native constrained decoding or a proof of perception semantics.

The unchanged production check schema and real perception materializer validate requested checks and derive their numeric values and RNG results. The benchmark also exercises the same successful-check admission predicate used by the actual onset reaction producer, including observer, source Action, world cause and dice outcome. Diagnostic conversion to check-or-done is only for exercising those boundaries: a no-check result is not a production perception admission. All explicit assessments survive in local evidence. Unknown assessments fail qualification; mechanical evidence agreement alone is not semantic proof. This candidate neither commits a world step nor creates a player observation, changes Agent knowledge, or adds a production algorithm or compatibility decoder.

Source validation covers Actions as well as state: each action has a unique identity, current base revision, existing Agent actor and targets in that actor's local belief entities. The [action contract](../../src/engine/contracts/model.ts) uses LocalEntityId targets; canonical Entity IDs are not interchangeable, and unresolved or ambiguous bindings remain legal. Validation does not translate local action targets into canonical identities. Invalid input stops offline, before HTTP. Every reconstructed or synthetic input records its own provenance; it is not an immutable replay.

Each frozen development corpus records its exact state, actions and oracle version. The four already-seen rule controls retain their class labels; a controlled concealment check may perceive either the acting person or the handled object, independently of the opponent supplying a Rating. This finite admissible set is derived from the validated source action and fixed before dispatch. Observing an unrelated object, changing the observer, source action, required difficulty or factual state remains invalid. A revised oracle never changes a terminal trial's reported qualification.

Each control gets one initial HTTP and zero repairs. Only four passing controls permit two repetitions of the complete captured 48-action, 29-target scene. Those repetitions remain exploratory, with unassessed open semantics. Stop on unknown billing, interruption or control failure, retain partial reports and do not restart terminal trials. Freeze code, data, prompt/schema/request hashes, concrete model, disabled thinking, prices, ordering and the six-call maximum before dispatch. Use the existing renewed budget and account for every request.

## Plan

Implement a benchmark schema, actual-request adapter and evidence validator. Exercise coverage and typed evidence failures through real world loading and check materialization. Run the frozen development diagnostic; use its evidence to decide whether to integrate explicit perception results through reaction creation and independent commit validation in a subsequent complete work unit.

## Verification

Verify all Fact value kinds, wrong or stale values and snapshots, unassigned or omitted pairs, duplicate and unused check keys, wrong observers/source actions, shared checks, unknown verdicts, and preservation of full request context. Exercise a valid check through the production perception entry and prove rejected evidence consumes no RNG and does not change source state. Run focused tests and check:fast before committing. Report formal, rule-controlled, unknown, full-scene and end-to-end outcomes separately; no controlled result establishes the 60-second gameplay goal.
