# Resolution Source Role Diagnostic

Artifact-Version: 1
Status: Approved

## Intent

Under the delegated [non-thinking gameplay experiment](0029-nonthinking-gameplay-efficiency-experiment.md), test whether exposing an existing mechanical source exclusivity rule resolves a recorded plan-repair failure. This is a bounded diagnosis of an actual targeted repair, not a reduced full-world batch or gameplay qualification.

## Contract

The kernel keeps its existing acceptance set: within one plan, actor aptitude, difficulty and factors cannot mechanically reuse the same source. Neutral permission, secondary and risk factors are included. Means and causal citations may still reference that evidence; separate plans may use it. Error messages identify both conflicting positions and roles. No field, factor or intended action is automatically changed or removed.

The candidate instruction remains research-only until prospectively evaluated. A paired diagnostic preserves the complete frozen request for the failed Lord Octa repair, including its original action, full state, candidate, existing feedback, schema and one-action scope. B keeps the recorded instruction; T adds only the explicit source-role rule. Both use DeepSeek Flash with thinking disabled, identical generation settings, one actual HTTP each, no retry or response-dependent adjustment. Freeze current code, source and actual request hashes, tokenizer admission, order and whole-pair budget before sending. A stopped or unknown-billing pair cannot restart.

Formal output, exact source/reference binding, the real materializer's acceptance and source-semantic review are separate results. A positive treatment response on this development failure is not general reliability, first-pass batch success or a playable step. Historical failures stay failed. Other failures from the same trajectory remain blockers.

## Plan

Preserve the failed source and lineage, clarify collision diagnostics, and exercise neutral/numeric and aptitude/difficulty collisions. Build the request clarification without changing the registered gameplay path. Verify the paired bodies differ only in the instruction, retain full source evidence, and report both outcomes and incurred cost. Promotion requires a separately frozen runtime identity and complete-world validation.

## Verification

Run relevant checks and check:fast before each local implementation commit.
