# Observation Coverage Diagnostic

Artifact-Version: 1
Status: Approved

## Intent

Test whether explicit per-observation evidence alignment and complete structured coverage can expose attribution and realization gaps missed by a single global acceptance. The actual recorded final review already contains the questionable observations; this diagnosis does not assume that missing input caused the missed checks.

## Contract

Keep the entire recorded context and generation settings. Add a reversible, source-hash-bound worklist containing each observation, the observer's own source actions and outcomes, existing claim-subject catalog entries, and explicitly referenced events. These are joins, not new semantic facts or proof of perception. Require exactly one classification per observation, existing evidence handles and consistent verdict/issue fields. Unsupported and insufficient both prevent qualification.

Use four frozen development controls in the complete recorded world: two permitted pending intentions and two unsupported attribution or realized-response claims. A paired control changes only its declared candidate observation and matching catalog label; the controlled pending outcome is identical across the pair. Labels remain outside model input. Score the designated observation, report all other classifications without treating them as gold. Require all four designated checks to classify correctly on their first response, with complete valid coverage. Only then allow one diagnostic of the original unmodified candidate. Never alter or override the historical gameplay review.

All requests use the existing budgeted transport, Flash with thinking disabled, original output ceiling, verified local context admission and no retry or repair. Maximum five HTTP requests; reserve their full worst-case cost in the review phase before dispatch. A transport failure stops the sequence, preserves unknown billing and emits a partial report. The original-candidate diagnosis is not a new game step or calibrated semantic approval. No default runtime integration occurs in this unit.

## Plan

Implement the diagnostic codec and coverage validator, verify exact source preservation and identity/coverage failures, then freeze all controlled inputs and local token counts. Run check:fast and commit before sending any model request. Record outcomes and costs in the existing work record; use the results to choose the next runtime intervention rather than immediately repeating a full game trajectory.

## Verification

Verify source hash and full round trip, action-owner versus claim-subject separation, complete unique output coverage and evidence membership. Bind source HTTP body hash, frozen code, each control context and exact outgoing body. Distinguish controlled-label accuracy, original ambiguous evidence and actual gameplay success.
