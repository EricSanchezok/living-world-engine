# Registered planning contract tail

Artifact-Version: 1
Status: Approved

## Intent

Make the successful complete-planning diagnostic layout selectable through the real game composition before testing full steps. Continuing autonomous optimization authorization covers this reversible optional integration; it does not approve default promotion or claim semantic success.

## Contract

An indexed reviewed planner may explicitly select the frozen planning contract tail when both action-local means positions and component-bound cause indices are enabled. The tail repeats the current indexed wire contract, the exact current action index set and count, and source-intent preservation instructions. It retains all preceding instructions, context, schema and repair evidence. It does not alter output, select evidence, omit actions or relax validators.

The renderer adds a trusted jsonObjectPostlude after the JSON schema and any repair tail. The complete postlude participates in request measurement, contract hashing and durable request evidence. Other transport modes reject this option before HTTP instead of silently dropping it. Defaults are unchanged.

The planning adapter validates its source projection and cause domain before producing the postlude. Current root, physical repair and targeted repair batches receive their own exact worklist counts and indices. Instructions have one maintained source; historical diagnostic records remain unchanged. The integration must reproduce the frozen diagnostic tail byte-for-byte for its original sources.

## Plan

Add the audited postlude rendering option, share the indexed instruction source, register the bounded planning adapter, and verify byte-for-byte diagnostic equivalence before a new full-step trial.

## Verification

Test complete context/output preservation, exact count and current source binding, invalid/mixed configuration, repair scope, transport placement after schema, accounting and audit evidence, rejection in unsupported modes, and actual registered game-entry routing. Run focused checks and check:fast before committing. Verify the recorded full diagnostic request matches the registered rendering before a fresh bounded gameplay trial.
