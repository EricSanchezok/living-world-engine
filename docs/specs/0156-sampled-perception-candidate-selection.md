# Sampled Perception Candidate Selection

Artifact-Version: 1
Status: Approved

## Intent

Test bounded parallel sampling and evidence-based selection after complete-context perception retains inconsistent references, reversed roles and unsupported information routes. The experiment trades additional inference for fewer sequential recovery attempts; it must measure that trade rather than assume sampling improves correctness.

## Contract

Each candidate arm samples three complete canonical perception directives concurrently from the same immutable source and exact original HTTP body. Preserve every subject, action, assignment, world record, law, model setting and output possibility. Every sample remains in the evidence record, including provider, schema, reference and mechanical failures. A check candidate must pass the same pure materialization, relation and repeated-check validation used before runtime RNG. A terminal report must pass complete canonical receipt materialization. Neither test certifies source semantics. Candidate screening draws no randomness and commits nothing.

If at least one whole candidate passes those gates, one selection call receives the complete source, all candidate values, rejection status and the original perception duties. It may select one mechanically eligible whole candidate or reject all. It cannot edit fields, merge reports, average states, invent a candidate or suppress a required check. The decoder returns the selected value exactly and binds the source, candidate pool, eligibility and request template. Runtime canonical validation remains authoritative after selection. An empty eligible pool stops without a selection call.

The selector uses the same official Flash model with thinking disabled. Its task asks whether a candidate preserves the actual observer, source action, current onset, information route, hidden knowledge and justified uncertainty. Sampling consensus and mechanical validity are not evidence of semantic truth. Correlated generator and selector errors remain an explicit risk.

## Plan

Freeze the complete forty-nine-subject initial perception source before RNG. Compare B/C/C/B. Each B is one exact original request. Each C permits three parallel proposals and at most one sequential selector, for at most ten HTTP requests total and three concurrent proposals. No repair, replacement sampling, check execution or world commit is permitted. Freeze the original request and a selector template before dispatch; bind only the actual candidate pool into that template afterward. Account for every proposal and selection call, cache usage, response type and complete arm latency. Review selected source semantics independently. Required-check continuation and complete player trials remain separate necessary qualifications under [Spec 0122](0122-player-action-efficiency.md).

## Verification

Exercise the actual TruthEngine and model gateway with only the external model boundary controlled. Verify pure check screening matches the runtime's committed requests, malformed and repeated checks fail before RNG, selected reports reach full receipt validation, rejected candidates cannot be selected, null selection fails explicitly and source or pool drift is detected. Preserve all original candidate fields and reject incompatible request adaptations. Run relevant checks and check:fast before the local commit and live comparison.
