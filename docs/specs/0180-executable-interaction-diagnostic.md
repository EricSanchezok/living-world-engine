# Executable Interaction Diagnostic

Artifact-Version: 1
Status: Approved

## Intent

Under the human-authorized [complete player experiment](0122-player-action-efficiency.md), implement and run the executable-interaction candidate through its real boundaries. The explicit continuation instruction overrides the [P0 promotion stop](../research/2026-09-22-step-e3-p0.md) for diagnostic execution. A failed screening result remains a failure, but does not suppress later diagnostic samples. Runtime correctness and spending limits remain binding.

## Contract

The diagnostic uses the incremental player foundation and a separate pinned producer. Action compilation jointly proposes the ordinary temporal/dependency result and an interaction program. Exact source text partitions retain every parallel member, condition, negation and commitment. Program admission is separate from schema validity and does not establish complete natural-language understanding.

The first rule set supports verbatim messages, observation of an existing fact and conserved quantity transfer. A source-authored, versioned capability states the exact endpoints, placement requirements, duration and allowed operation. No capability is inferred from a shared placement, a natural-language command, an unbound collective or model confidence. Missing, changed, ambiguous or inaccessible sources remain residual. W0 receives no new world facts; authored capability controls are labeled W1 and are shared by both arms.

Preparation-time bindings persist with the diagnostic execution state and preparation. The diagnostic producer keeps that journal frozen during completion. Reaction replacement uses its newly compiled binding only within the current completion; an ongoing replacement without a persisted binding uses ordinary adjudication at the next boundary. Old action bindings cannot authorize the replacement. Each component executes locally only when all current work is covered, its original Activity is due, and all guards hold against the current source. Otherwise the entire component uses ordinary open adjudication. Candidate operations never mutate the source. Original receipt, quantity, causal, observation, temporal, dependency and atomic-commit boundaries remain authoritative. A rejected local candidate falls back without discarding its cost or evidence. Delivery never means belief, obedience or goal achievement.

The repaired B and C producers both select the existing exact observation action dictionary from [0122](0122-player-action-efficiency.md). It interns complete records and ordered sequences without dropping actions, changing observer scope or reducing batch cardinality. Expansion must recover the original shared context hash. Original output schemas and semantic validation remain authoritative; smaller input alone does not establish equivalent model quality. Producer versions and the codec hash are pinned for the repaired experiment.

Source compilation screening uses all three complete 49-subject development sources with alternating B/C order, no first-output repair or resampling, at most 60 physical requests and CNY 100. Complete player diagnostics use fresh initialization, all 48 autonomous Agents and one external participant, three canary pairs followed by thirty paired episodes in six fixed categories with three inputs per episode, subject to the 2,400-request and CNY 300 aggregate ceiling. Every failure stays in its original denominator. Subsequent diagnostic execution does not retroactively qualify a failed arm. Initialization and imported/shared initialization provenance are reported explicitly.

The user-authorized repair validation R1 has an additional CNY 100 ceiling and at most 800 physical requests in a separate evidence root and budget journal. It freezes the repaired producers, retains the original 33-pair task queue, full cohort, batch cardinalities and dispatch limits, and continues through diagnostic failures until that queue or its spending boundary is reached. Initialization, failed attempts, repairs and unknown-usage reservations all count. Original P2 measurements remain immutable; R1 observations cannot fill the original producer's missing rows. The runner rejects a root containing the other phase's manifest, budget or episodes.

Before inference, freeze code, model metadata, disabled thinking, source hashes, prompts, request limits, category inputs and acceptance contracts. Count every physical request, rejection, repair, fallback and discarded candidate. Useful feedback and goal completion require actual source-supported results; generic success prose is insufficient. Report unexecuted measurements as missing, never zero.

Operational recovery may resume a drained arm only after a contiguous prefix of durably recorded inputs, with the current state matching the last checkpoint and no live player run. Completed and failed inputs are immutable and never resent. An unknown-usage request follows the explicit evidence-review and full-reservation quarantine rule in [0026](0026-full-step-efficiency-experiment.md); quarantined input trials stay closed and only distinct later inputs may proceed. Administrative runner recovery retains the frozen producer and request protocol, rejects changes to engine, prompt, model, world or task bindings, and records both code revisions. Report recovery downtime separately from measured player-input waits.
