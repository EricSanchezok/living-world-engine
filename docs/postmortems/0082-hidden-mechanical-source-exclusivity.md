# Hidden Mechanical Source Exclusivity

Artifact-Version: 1

## Executive summary

A non-thinking full-world step failed after a targeted plan repair repeatedly used the same fact as both permission and risk. The validator enforced an exclusivity rule absent from the model-facing factor instructions, and its error named the source without identifying the conflicting positions.

## Summary

The complete trajectory used eighty-five model requests and committed no step. This was its first terminal component error. Other format, reference and causal failures remain separate blockers. Fixing this contract gap alone cannot establish playable behavior.

## Timeline

- The factor representation described permission and risk as neutral, zero-step notes.
- A repair returned the same fact in two such roles.
- Two bounded repairs retained the collision despite correctly bound previous candidates.
- Ledger inspection identified both conflicting factors and confirmed the existing kernel rule.
- Collision diagnostics gained exact positions; an additive instruction entered a separately frozen research comparison.

## Root cause

The model-facing contract explained numeric factor constraints but omitted the cross-field source uniqueness rule. Describing neutral factors as notes could reasonably encourage using a relevant fact for both permission and risk, although the engine rejects that representation. Generic source-level errors concealed which assignments competed. This establishes a contract omission; stochastic response improvement still requires a prospective comparison.
