# Perception Catalog and Check Materialization Disagreed

Artifact-Version: 1

## Executive summary

A full-world diagnostic recovered action compilation but exhausted perception repair before the first state commit. The model selected Agent actors and local-entity targets that the context advertised, while the runtime required canonical entities. Generic output fields admitted those selections at schema validation.

## Summary

The fix aligns field types, advertised uses and commitment-round reference inventories while retaining every contextual row and the original output evidence. It does not map local identities, remove required targets or substitute completion for a failed check. The stopped run remains a failure.

## Timeline

- The full-world run completed initialization and repaired all compilation batches.
- Perception selected Agent and local-object handles for entity-only fields.
- Repair recovered one group but exhausted the next, leaving the world at its original revision.
- Ledger context and parsed-output artifacts established the catalog/schema/materializer contradiction.
- Typed fields, a shared cause inventory and a per-round resolver aligned the executable interface; all descriptive rows remain visible.

## Root cause

Truth stages shared one descriptive reference catalog, but perception had narrower executable field types. Its role instructions also mentioned discrete random requests and same-response references that its directive could not execute. Existing tests primarily used completion-only perception fixtures and therefore did not detect the disagreement. A related lifecycle mismatch exposed committed checks in later-round contexts while the materializer retained the initial resolver.

## Guardrails

The [perception reference contract](../specs/0100-align-perception-reference-contracts.md) separates legal selection from preserved contextual evidence. [Real perception-entry tests](../../src/engine/mechanics/__tests__/perception-references.test.ts) cover exact schema paths, valid checks and explicit null targets, rating validation, complete repair evidence, unchanged RNG after rejection, committed-check causes and unchanged other-stage catalogs. The test provider disables its Truth scenario adapter so a requested check cannot silently become completion.

## Remaining limitations

Typed schemas do not prove that a model selected the intended target or requested every necessary check. Provider enforcement, first-pass success, open semantics and complete gameplay latency require fresh model and execution evidence. Historical failed runs remain failures; no automatic local-to-canonical binding or target removal is credited as recovery.
