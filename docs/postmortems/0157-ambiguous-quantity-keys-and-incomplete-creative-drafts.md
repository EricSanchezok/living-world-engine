# Ambiguous Quantity Keys and Incomplete Creative Drafts

Artifact-Version: 1

## Executive summary

Frozen live qualification exposed numeric choice keys that resembled their values, unmaterialized props inside accepted creative descriptions, and a valid JSON decision with an invalid recipient. The runtime binds quantity keys to values, checks creative entity coverage in the existing admission request, and repairs only invalid decision fields once.

## Summary

The two-cell payment did not occur even though its quantity was available. New actors could be spoken to, while independent items in their appearances had no identity. A shop inquiry produced some observation prose before an invalid recipient stopped the remaining action locally. These remain failed samples.

## Root cause

Candidate ordinal names invited numeric interpretation despite different labels. Creative schema validation covered declared entities but did not establish coverage of descriptions. A whole-draft coverage judgment still missed carried objects and furniture, including after a repair; it also received the creator's unsupported claim that everything was registered. Coverage now asks about each persisted passage against the actual inventory in the same admission batch, excluding that audit summary. Strict batch validation discarded valid independent answers with one invalid key. Long action contexts also buried the current submission among prior dialogue; highlighting the current request at the affected questions preserves context while clarifying its priority. Deterministic fixtures supplied correct keys and complete drafts, so they did not expose these model behaviors.

## Guardrails

[Runtime regressions](../../src/engine/direct/__tests__/runtime.test.ts) bind two units independently of an earlier 120-second candidate, verify the current-request prompt fields, exercise one missing-entity correction and a second failure, and replay without duplicate effects. They also accept exact bound canonical placement IDs, preserve parent ordering, and retain existing observations when optional expansion fails. [Decision regressions](../../src/engine/models/__tests__/decision-v2.test.ts) retain valid fields across one correction and stop after a failed correction. [The direct runtime reference](../game-design/direct-runtime.md) and [narrative contract](../game-design/narrative.md) own the resulting behavior. Retired inputs remain in the [experiment driver](../../scripts/experiments/immersive-narrative.ts); the next cohort uses distinct frozen inputs.
