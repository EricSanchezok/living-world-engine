# Report Check Errors Lost Assignment Paths

Artifact-Version: 1

## Executive summary

A complete player diagnostic exhausted perception repair after a report borrowed a different observer's fixed check. The receipt validator rejected the dependency correctly, but its generic error omitted the report, citation and legal check choices. The next full report repeated the same mistake. A successful roll was also narrated as proof of an unestablished remote delivery; fixing the citation cannot certify those semantics.

## Summary

Execution bedbb17a-da76-4ebe-bba8-d4aebb823164 covered forty-eight autonomous NPCs and one external player. It issued twenty-one model HTTP calls and stopped after 107.705 seconds from player submission, with no feedback or world commit. Perception used five calls; planning was never reached. These are failed-run observations, not a successful latency baseline.

## Timeline

- The committed-check continuation at Ledger sequence 341 contained eighteen assigned pairs and three fixed checks over the complete forty-nine-action source.
- The first report output failed evidence-kind schema validation. The report at parsed sequence 364 passed schema but target 5 cited the successful check belonging to target 2, reversing both observer and source action.
- The repair source at sequence 370 carried a generic receipt dependency error with an empty path.
- Parsed sequence 379 repeated the same invalid citation, and rejection 382 ended the stage. The report also attributed a future written reply to an already received message; no deterministic citation repair resolves that semantic issue.
- A zero-HTTP reconstruction reproduced the complete action and truth projections, deterministic check IDs and all three RNG results. Both parsed candidates isolated the same error at reports[5].checkRefs[0], with no legal replacement check for that observer/action pair.

## Root cause

The model selected from a global check catalog and confused two related characters' opposite actions. The late receipt validation boundary emitted only its first generic exception after report sorting. It exposed neither the original draft position nor other independent failed dependencies, leaving repair to rediscover the affected join across the full context. Existing rejection tests established safety but did not verify actionable repair evidence through the actual generation loop.

## Guardrails

- [Draft check diagnosis](../../src/engine/mechanics/onset-receipts.ts) collects every invalid citation before sorting, with original report and citation ordinals, assigned observer/source identity and only mechanically usable check references. It does not change a citation, verdict, stimulus or committed result. Complete receipt validation remains authoritative.
- [The real-entry regression](../../src/engine/benchmarks/step-efficiency/__tests__/perception-report-check-bindings.test.ts) requires all independent diagnostics in one repair, preserves shared checks for the same observer's explicitly cited actions, and verifies fixed outcomes and RNG. Its diagnostic expectation fails with the generic receipt-only implementation.
- [The field-domain experiment](../specs/0130-perception-report-field-domains.md) compiles these existing joins and fixed results into per-target generation constraints. It remains experimental; schema and receipt admission do not establish sensory access, delivery or narrative fidelity.
