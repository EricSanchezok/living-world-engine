# 黑沼知识、传闻与秘密

## 认知契约

本文是认知层参考。世界历史、Viz 与已确认超自然现象由 [`world-bible.md`](world-bible.md) 拥有，组织结构和资源由 [`factions.md`](factions.md) 拥有；本文只定义这些事实如何被不同主体知道、误解、隐瞒与验证。

Canonical truth 只进入 Truth Engine 与获准的事实裁决，不直接注入 AgentMind 或客户端。Agent 只能持有自己的 local entity、evidence、claim 与可能歧义的 binding；“某组织知道”在本文中只表示列出的具体领导、见证者或档案持有人知道，不能扩展为全体成员共享。

来源标记沿用 [`source-ledger.md`](source-ledger.md#权威来源)：**移植**是 v11 明示事实或其作者给出的传闻真假，**阐释**是从地点和见证条件推出的最小认知分配，**原创**是为了让秘密可调查而补出的证据持有人或确定答案。上游未给答案的谜题保持未决，除非本文明确标为原创定案。

## 开局知识层级

| 层级 | 开局持有者 | 可进入的内容 | 不自动获得 |
|---|---|---|---|
| 公共常识 | 黑沼堡居民、常来商旅与玩家各自通过实际接触取得 | 地区大致格局、公开统治者、主要道路与市场、Viz 有价值、Rangers 招募等 | 远方即时事件、传闻真假、秘密身份、组织内部决策 |
| 流言 | 在港口、市场、旅店、宴会或商队中听见该条说法的具体主体 | 二十条原作传闻中的一条或数条原文主张，不附作者真假标签 | 其他未听见传闻、canonical truth、传播者未说出的来源 |
| 机构记录 | 受权阅读的总督、祭司、军官、学者、商会职员 | 巡查报告、账册、航海日志、邀请册、旧档案等 | 记录发生后的变化、其他机构的私档、记录真实性保证 |
| 亲历秘密 | 事件参与者、现场观察者、被直接告知者 | 自己实际观察或可追溯证词覆盖的部分 | 事件的完整因果、他人动机、未观察地点 |
| 单元秘密 | 阴谋发起者及其明确联络人 | 当前计划、口令、路线、承诺 | 同一大势力其他单元的计划与现场进度 |
| 无人解释的事实 | 没有主体拥有完整解释 | 只能通过物理痕迹逐步发现 | 作者视角的共同原因与完整谜底 |

玩家开局认知由[玩家边界](design-brief.md#玩家边界)定义。二十条传闻都是可发现的传播内容；只有当玩家实际听见、读到或调查到某条信息时，才创建相应 evidence 与 claim，不附作者真假标签。

## 证据传播与保密

1. 亲历生成 observation，只证明感知范围内的事实；黑暗、charm、恐惧、距离与伪装会降低或改变证据质量。
2. 转述生成 testimony，必须记录来源主体、传递时间与原句；二手证词不能伪装成第一手观察。
3. 档案、账册、命令与地图生成 document evidence，但可能过时、被删改或只覆盖编写者职责。
4. 同一主张的多份证据只有在来源真正独立时才增加可信度；从同一酒馆传闻复制出的十个版本仍是一条来源链。
5. Agent 可相信错误传闻并据此行动。Truth Engine 在裁决后果时使用 canonical truth，但不得把纠正信息偷渡进该 Agent 的思考上下文。
6. 组织中的报告沿真实路线传播：现场人员到 commander、信使到总部、船只到港、账册到审阅者都消耗时间；组织关系不能跨距瞬时同步。
7. 发现一项秘密不会自动揭露关联网络。识别 Rinisar 的计划不等于知道 Raven 总人数，找到 Atacyl 遗物不等于知道 Autse 身份，确认黑石同材也不等于解出所有陨山异常。
8. 玩家公开、出售或伪造信息后，接收者依据来源关系和现有 belief 更新置信度；事实不会因为玩家声称而直接改写 canonical state。
