# 正文复核执行参考

语义要求由[审校规则](../adjudication-policy.md)负责；本页描述调用、复用与修复。审校结果仍是来源证据，不能自动批准开篇设定或运行模块。

## 调用与费用控制

`adjudicate-fanren.ts` 默认每次处理一个批次，使用 `deepseek-flash`、`low` effort、单并发。DeepSeek 账户只允许 Flash，并须明确关闭思考或使用 low；`--model`、`--effort` 不能越过这一限制。切换其他供应商时，`--profile-base` 和对应模型、推理参数仍按该供应商能力校验。实际生效模型、推理设置和用量以保存的调用 audit 为准。低推理档位仍会消耗推理 token，不是硬性推理额度；它也不能替代编辑检查。

后续地区初审工具 `propose-fanren-regions.ts` 也默认使用 Flash/关闭思考，可用 `--thinking enabled` 明确启用 low；DeepSeek 模型仅允许 `deepseek-flash`。其输出仍须由编辑对照来源处理，不能直接关闭地区制作项。

```sh
npx tsx scripts/world-authoring/adjudicate-fanren.ts --start batch-0001 --count 398 --plan
npx tsx scripts/world-authoring/adjudicate-fanren.ts --start batch-0001 --count 2 --max-calls 6
```

`--plan` 校验来源和可复用报告，输出待处理批次与压缩前后的上下文、schema 字节数，不初始化模型网关、不请求网络、不写审校结果。字节减少不是实测 token 或费用减少。

`--max-calls` 限制本次所有工作线程合计的生成请求，包含修复，默认是请求批次数的三倍。每次生成最多一次网关传输尝试；余额、认证或配置故障停止后续派发。信号停止保留进行中的结果，并在每次后续付费调用前重新检查。来源校验与报告复用不计入付费请求。元数据查询不是生成请求。

汇总中的 `generationRequests` 是准入网关的请求数，包含可能在队列中被取消的请求，用作保守上限；实际调用结果和 token 以 audit 为准，不能将排队取消计作已付费调用。

[复核优化验证记录](../validation/source-review-optimization.json)保存离线回放、传输体积、实测请求及 token 账目。两批试跑并非同一任务的受控对比，不能把它们的差额当作稳定节省率或质量等价证据。

## 来源完整性与复用

每次请求均带上全批原文段落和全部候选语义。短段落编号可逆映射到真实章节和偏移；候选精确引文保留，指纹及偏移在本地校验与存档。正文没有被摘要替代，段落数量在 audit 中如实记录。

同批初审与修复使用固定任务指令，变化的修复数据放在完整候选、正文和覆盖清单之后，保留可供供应商复用的请求前缀。是否命中缓存及实际优惠仍以供应商用量回报为准。

已通过的报告须重新通过原文、候选、语义规则、原审计身份、当前结构和完整覆盖检查，才可跳过调用。更换模型、并发或传输编码不会重写合格报告的原模型身份与审计证据。原文、候选或语义要求改变会阻止复用。`--fresh` 显式要求重新审校，旧报告会在替换时存入忽略缓存；同一执行身份下的未通过草稿可接续修复。

## 局部修复

初次响应仍须逐项审查所有对象、事实、别名、已有问题，并独立扫描遗漏与身份关系。局部修复仅重写可定位的错误行，已通过行和已经发现的有效遗漏保持原样。补丁不能修改非目标行、遗漏目标、重复编号或引入额外条目；合并后重新执行完整校验。无法可靠定位的损坏回退完整响应，不凭猜测合并身份。

原始响应、失败和每次请求的调用证据保存在忽略的来源缓存中。缓存续跑、结构检查通过和模型判定 supported 都不能替代编辑审定、全域覆盖及真实游玩验收。

完整响应若因一个已识别的表示错误被供应商适配器拒绝，脚本会在付费重试前尝试本地恢复：严格 JSON 语法扫描只允许对象末尾的字符串值后出现一次畸形 `,"}`，删除其中多余的 `,"`。字符串内部的相似文字保持原样。多个损坏点、其他修改方式、重复键、多个根、截断及不完整内容均拒绝；恢复后仍须通过完整 schema、候选覆盖和来源引用校验。此规则仅用于 `complete-review`、正常结束且原审计明确拒绝的响应；不处理 `targeted-repair` 补丁，其他情况继续原修复路径。

新响应和同一执行身份的失败缓存都能触发这一检查；后者可在 `--max-calls 0` 下完成，`--fresh` 仍跳过旧缓存。报告的 `localSyntaxRecovery` 保存策略、原始 UTF-16 删除区间、原始与恢复文本指纹、完整结果指纹、原审计指纹和缓存身份。原缓存不改写，原调用仍记为 `rejected`，不会冒充模型直接通过。后续复用与来源证据索引均须重新读取该缓存、重演同一删除并验证派生证据链；因此该响应缓存与正文一样是本地可追溯资料，清理后报告不能继续通过复用或有效来源证据检查。未提供缓存读取能力的证据消费者同样拒绝派生报告。报告不内嵌原始正文或模型响应；表示恢复不构成语义批准。

编辑对照原文发现的问题写入[候选修订](../reviews/editorial-findings.json)，绑定候选、来源报告和证据定位，供地区写作接续；原模型输出与调用记录保留。单批证据无法确定开篇状态时，后续可以补充跨章依据或明确标为原创，不能把“未知”解释为“不存在”。正文定位以结构化 `evidence` 为准，模型自由文本中的段号或时间表达仍须对照原文检查。
