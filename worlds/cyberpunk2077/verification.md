# 夜之城首版验收记录

验收日期：2026-10-17。本页保留 1.0.0 首版的验证与限制；1.0.1 的付款修复及十二种出身试跑见[真实模型验收](live-verification.md)。当前运行包的内容指纹和规模以[生成清单](authoring/coverage.json)为准。

## 确定性运行验收

[持续验收测试](../../test/cyberpunk2077-world.test.ts)通过实际 ZIP 导入、LocalDatabase、WorldHost、默认运行算法与持久化入口，仅替换外部模型 HTTP 响应。它证明的是这些确定语义下的引擎行为，不是在线模型每次都能正确理解所有行动。

| 检查 | 结果 |
|---|---|
| 世界校验 | 实体、引用、认知、机制与模型 Profile 均通过加载器校验 |
| 确定性构建 | `build.mjs --check` 检查运行 YAML、身份指南和作者目录一致 |
| 十二种入口 | 逐一导入后接管既有人物；个人现金、工作地点、住所、资产和合同均可读取 |
| 熟人关系 | 每种身份的三名联系人都保有对该角色的身份绑定，角色也认识他们 |
| 独立人物 | 接管一人后，其余一百名人物和六个支付服务的控制策略仍为模型控制 |

## 内容审校

按 repo-review 对角色背景、关键关系、时间安排和新文案做人工检查。资料依据与原创标定分列在[作者参考](authoring/README.md)和[来源目录](research/sources.md)。私人合同内容保存为有限受众事实，密封温控容器使用不泄露内部内容的外观，回忆历史强尼没有绑定当前实体位置。800 欧元的管道报价具有明确的未付款状态，与已垫付债务区分。关系使用单条客观边及双方各自记忆，避免重复保存等价关系；场景自由补全在此验收版本关闭。

## 在线模型与输出额度

在线校验使用实际 HTTP 导入、创建、接管与行动入口，服务运行于指定的 `.livingworld-v23/` 数据目录。实例持有世界和模型配置的独立快照，重新导入后使用新实例检验。

多人开场的主裁决请求触发 JEV 的 `max_tokens_exceeded` 拒绝。输出额度对照试验中，8192 token 的 DeepSeek 回退全部用于推理，正文为空，修复也未恢复；因此本世界显式选择 `decision-deepseek-long`，保留相同场景和并发参与者，将该回退的输出上限设为 32768，其他世界原有 Profile 不变。这个上限是原回退的四倍，不能当作成本不变的优化。

一个完成的回退样本输入 67581 token、输出 12589 token，其中推理 11049 token，耗时约 64 秒；它在主裁决失败后额外调用一次模型并提交有效结果，没有继续修复。该样本覆盖两个世界步进及文字呈现，完整链有 21 次模型调用，其中 20 次接受、1 次传输失败；不能把单次回退成本当成整轮成本，也不能据此断言每轮都会有相同数量的调用。

内容审校发现一次生成对白把标题中的五年租约说成七年，世界合同及账本并未相应改变。运行源为此把五年期限同时写入条款、相关人的既有认知与 `term-years` 数值事实。明确字段提供更好的依据，但不能保证模型永不误读；涉及钱款、期限、身份和原作经历时，仍需比较实际世界状态与呈现文字。

含明确期限字段的 O01 在线样本完成观察开场，推进两个步骤、60 秒世界时间，三位熟人分别陈述诉求，生成对白正确保留五年租期。只读核对持久化状态：个人现金为 18000、维修专户为 12000，两份协议均未签署，800 欧元报价仍未支付，期限数值为 5。浏览器角色视角也展示实际现金、住所、产权、熟人和合同，行动输入可继续使用。

O02 的终端输入试验未通过付款验收：模型将“提交付款申请”解释为使用另一台测试设备，支付服务没有收到金额并继续等待；呈现文字却出现了付款表述。账本仍为项目 48000、艾达 1200、个人 9000，试验实例已手动暂停并保留。当前六个账户明确采用现场语音受理，角色的既有认知和教程都要求直接向终端说出业务内容；仅有付款描述不能作为落账证据。

语音申请的续办试验另发现一个通用引擎缺陷：账户仍保有“支付 6000 欧元”的私人证据，但观察游标推进后，该金额不再进入行动的数量候选。引擎现从行动者自己的保留证据提取候选，同时区分转账收款人与对话回复对象；没有读取其他人物的秘密，也没有为本世界特设付款通道。[回归测试](../../src/engine/direct/__tests__/runtime.test.ts)先复现旧实现遗漏早先约定的金额，再验证新实现保留该金额、排除另一人物的私下报价；相关引擎与世界测试共 125 项通过。

修复后的同一在线实例在玩家未重复金额时，正确选择向艾达转账 6000 欧元。裁决上下文含项目余额 48000、已送达申请及单笔 10000 的采购授权，但 JEV 本次仍返回 `failed`；实际余额保持项目 48000、艾达 1200、个人 9000。该响应未提供可核验的拒绝理由，不能据此断言是合同未签或额度不足。这个样本证明金额记忆和收款人选择已恢复，**不算在线公司付款成功**；复杂业务的模型裁决稳定性仍是已知限制。确定性公司付款测试证明合法裁决提交后确实由项目账户扣款，并不代替这个在线结果。

## 工程检查

`npm run check:fast` 通过，包含 363 个测试文件、2420 项测试、类型检查和六项治理检查；ESLint 有三条现存未使用声明警告，无错误。本世界的四项验收测试包含语音业务申请，世界加载校验和确定性生成检查通过。实际 DeepSeek 服务预检通过。运行日志、Ledger 与浏览器截图保存在 Git 忽略的本地验收目录，下载资料和打包 ZIP 同样不进入提交。

引擎修复后重新启动本地工作台，首页、世界目录和实例目录均返回 HTTP 200，目录包含 Blackmarsh 和夜之城。旧测试数据及开发缓存已保存在被忽略的数据目录内，未删除已有实例。交付开局使用最终世界源新建，处于第 0 步，角色及共同账户资金尚未消耗。

## 验收边界

结构校验与测试不能证明所有人物的每句生成对白都忠实原作，不能代替长期游玩、所有职业行动、全部任务分支和多百人性能测试。初始完整人数不等于一回合同时进行了相同数量的模型调用；运行调度以实际可见事件和人物活动为准。预置资金和能力是玩法标定，不能拿来声称原版游戏的数值已被复刻。
