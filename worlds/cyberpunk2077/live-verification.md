# 十二种出身的真实模型验收

本页记录 2026-10-17 的真实模型验收：经过问题修复与恢复，十二种出身均完成所列开场活动，十二份最终状态均通过精确机械回放。确定性运行契约另见[首版验收记录](verification.md)。所有行动经 HTTP 创建、接管和提交入口执行，模型调用使用已配置的实际服务，不替换响应，不直接改存档制造成功。原始请求、完整状态、账本和模型审计保存在被 Git 忽略的本地验收目录。

对象为运行包 1.0.1，共 293 个实体、107 个 Agent（其中 101 名人物、6 个账户服务）。本次正式实例固定世界指纹 `sha256:5728b602266862392dd9755419074e5056cdba133eaa88eb04ed2cd375440647`；生成文件摘要为 `6071f8fbd4d2d98eebd86da56ce022fbea83405715a7aa24ed9ba748992311d0`。通用运行时修复提交为 `4af97c05`；测试跨越修复前后，恢复记录保留各阶段的提交号与失败原因。

## 公司付款裁决

原始失败调用为 `f33eebdd-4415-49a9-9dec-96d47616277b::rt:model-audit:6528c77b4680f9ed7f7cd6c6292ae0ed01ce65bc049d4bd7ce43ceff37c2f043`，Ledger 序列 7413–7426。项目账户持有 48000 欧元，收到向艾达支付 6000 欧元的申请，岗位授权上限为单笔 10000 欧元；该次裁决为 `failed`，未发生付款。

冻结现场对照保留原有批次、全部局部事实与模型输出契约。JEV 原问题重复三次均拒绝；补充电子转账措辞、突出付款依据、细化成功与失败条件、补充已送达话语的来源，分别仍拒绝三次、三次、两次、两次。诊断问题能识别余额、授权和不必签六个月框架，却未能稳定识别已送达申请。它提供的各项概率不是实际游戏随机数，也不能据此推定唯一内部原因。

同一完整现场使用 `decision-deepseek-long` 的两次正向对照均判为可执行；将待执行金额改为 12000、保留没有额外批准的事实后，负向对照判为失败。这些是冻结请求的语义对照，不能直接算成真实付款。一个正向样本输入 27332 token、输出 11985 token，其中推理 11573；另一次正向输出 13238。不同 Profile 的成本和延迟不同。

运行包 1.0.1 的世界裁决选择 `decision-deepseek-long`，人物私有行动选择保留 `decision-jev`。采用现有模型绑定，没有新增裁决调用、拆小批次、强制成功或为夜之城写入框架特例；选择理由见[决策 0246](../../docs/decisions/0246-night-city-world-adjudication-profile.md)。

## 实际公司账户结果

实例 `9d290790-058c-4cd9-b2c0-00067a551d36` 经真实模型提交后，项目账户由 48000 变为 42000，艾达由 1200 变为 7200，负责人私人现金保持 9000。付款由账户 Agent 实际提交 `transfer`，不是负责人把说话当成扣款。艾达在后续交流中确认到账，六个月采购框架没有被自动签署。

以同一提交 ID 重发原 HTTP 请求，返回 200，完整世界状态与 revision 5 均保持不变。随后另行提交未获额外批准的 12000 欧元申请，运行结束至 revision 7，没有第二次转账、任何余额变化或新合同事实。该次是“未执行”的状态证据；账户没有给出一段显式拒绝对白，不能把它写成已经验证了拒绝解释的交互体验。最终状态可以精确机械回放。

真实运行还发现并修复了一个通用调度问题：玩家动作已结束、现场人物仍有活跃回复时，不能回落到全体待行动人物。复现与永久测试见[事故记录 0169](../../docs/postmortems/0169-active-reply-admitted-unrelated-agents.md)。修复后的公司交流只执行现场相关人物，不通过关闭远处角色或缩小世界来规避问题。

急救员的第一次交流在第二段征求同意前遇到 `action.tool = null` 的结构校验失败；该字段不参与说话。修复外层形状后，仍由原有的已执行分支校验器检查实际目标、数量和工具，没有放宽用到的引用。原失败及其修复调用完整保留，见[事故记录 0170](../../docs/postmortems/0170-unused-null-tool-blocked-player-speech.md)。

## 验收方法

[自然语言用例](authoring/live-cases.mjs)为每种身份安排熟人交流和具体职业行动；[运行器](authoring/live-playtest.mjs)使用公开 HTTP 入口创建独立实例，记录初始资产、双向熟人绑定、每次提交前后的状态、实际操作与观察、最后的机械回放结果。状态读取使用本地数据库的只读入口。运行器不会根据结果选择性删除失败记录。

执行命令为 `npx tsx worlds/cyberpunk2077/authoring/live-playtest.mjs --tag manual-check-20261017 --concurrency 2`；可用 `--roles lead,editor` 限定身份。它调用真实收费模型，普通单元测试不会自动执行。每次新验收使用新名称；已存在的会话必须先检查。若本地 HTTP 读取中断，可用相同 tag 和 `--resume` 继续：保留原实例、提交 ID、初始状态和恢复记录，跳过已完成步骤，并创建尚未启动的身份实例。运行器仅对只读 GET 做有限重试，不自动重新创建或重复提交行动。已失败步骤默认停止；查明并修复原因后，显式加 `--continue-after-failure` 才能在同一存档执行后续行动。原失败步骤保留，结束状态标为 `completed-after-recovery`，不能冒充首次全通过。对于已查明的外部传输失败，`--retry-failed-step work` 会归档失败请求及快照，使用新的提交 ID 在同一存档重试原文；不会改写失败记录或把未执行动作记为已执行。

验收比较真实数量、事实、放置与被实际收到的观察。成功叙述不能代替落账，检查不等于修复，低速测试不等于全速合格，口头方案不等于合同已签或收入已收。有限样本也不能证明所有未来职业分支和全部对白都正确。

## 恢复记录与结论范围

这不是十二条轨迹首次全部成功。急救员保留了说话结构校验失败，修复后在同一实例继续；水泵操作员第一次职业动作遇到上游连接关闭，尚未执行诊断，检查原因后用新提交 ID 重试相同原文。HTTP 只读查询中断后也恢复了原会话。急救员的一轮后续复核超过运行器的十分钟墙钟保护而暂停，检查已落账的处置与待回复人物后恢复运行，没有重做急救或再次扣除医材。

跟进动作是在看到前一次真实回复后编写的，例如取得安娜同意后才执行接点维护、确认丹同意后才转向他提供急救。用例保留这次轨迹的原文；在新的随机轨迹中，必须重新确认当前状态，不能把这些自然语言前提当作引擎已经认可的事实。

验收覆盖每种身份的初始资源与熟人绑定、实际收到的交流，以及一项有状态证据的职业活动。它没有穷尽每件资产的全部用途、所有合同分支和后续人生。工厂暂用通用组件数量，未区分原料与成品型号；乐队和记者的本次行动没有新增独立报告实体。模型配置也有明显延迟代价：多人物、多阶段的回合会持续数分钟，暂停和人工检查使墙钟耗时更长，不能据此声称已达到低延迟游戏体验。
