# 1.1.0 实模验收与收尾记录

本次按用户新的收尾范围，用既有日志、离线回归和 4 次针对性 API 请求修复已定位故障，没有重跑十二条完整轨迹。当前运行包仍为 1.1.0，执行算法升为 `direct-world@12`，实例格式为 v33。以下先记录针对性验证，再保留此前未完成的大规模验收；[1.0.1 的十二出身验收](live-verification.md)不能替代 1.1.0 的全量实模证明。

## 针对性收尾验证

**职业动作授权。** 失败请求没有丢失玩家原文。模型把原文对象内附带的上一轮对话当成了当前命令。修复把完整当前输入与完整历史参考分别呈现，直接以 `originalSubmission.rawText` 及其目标、手段为授权依据。历史仍可解析代词，不能覆盖新指令，也不能代替玩家作出新承诺。没有放宽 `outside_scope` / `unknown` 拒绝，没有删题、减上下文或增加正常裁决轮次。见[事故记录 0180](../../docs/postmortems/0180-current-request-hidden-behind-historical-discourse.md)。

使用真实 `prepareActions → DirectDecisions` 从失败现场重建完整 203 题请求；除授权来源布局、对应规则和这一道授权题外，其余 202 题及输出 schema 保持一致。保持同一模型、配置与注册表，每个传输只尝试一次：

| 验证 | 实际结果 | 模型耗时 |
| --- | --- | ---: |
| 当前明确要求本地试播 | `authorized`、`succeeded`，203/203 题齐全 | 69.149 秒 |
| 当前明确禁止试播，历史仍保留同一上下文 | `outside_scope`、`failed`，203/203 题齐全 | 63.714 秒 |
| 复用第一条裁决，声明本次器材操作的效果 | 能力声明通过结构与绑定校验 | 11.007 秒 |
| 对效果进行原有补充裁决 | 实际效果获准，进入机械结算 | 6.144 秒 |

四次调用输入合计 169886 token、输出 30770 token，其中推理 27103 token；均无重试。硬预算原为 6 次，实际在 4 次后停止。另两次辅助脚本因缺少运行身份而在联网前失败，新增调用均为 0；这些记录同样保留，未计为成功验证。

保存的真实输出再次经过零联网的原生准备、结算、属性应用和角色感知：经纪人使用器材与工作母带，新增本地播放接线、母带播放路由及试听关注点三项事实，并收到对应行动的观察。原有事实、母带内容与产权、公开传播许可、全部数量及位置均未改变；撤回授权时没有经纪人的动作、效果或回执。验收覆盖此前被误拒的首个试听动作，**没有把后续填写报告、两位成员的反馈或整段演出任务计为完成**，也没有编造“接口无损”的测量结论。这是冻结现场的针对性模型与结算验证，没有把旧 schema 32 存档迁移为新存档。

**公司采购。** 新永久回归通过当前 1.1.0 世界、真实持久化 WorldHost、Direct 执行与交易核，只替换模型 HTTP 边界。6000 付款使公司 48000→42000、艾达 1200→7200，私人 9000 不变；后续实际交付使艾达六台控制器变为零、负责人持有六台。重启 Host 后以原 submission 和旧 revision 重发，模型调用、余额、状态、运行记录均不增加，完整状态可精确回放。12000 候选经过世界拒绝后，资金和原有事实均不变；世界金额权限仍是提供给语义裁决的规则，测试替身的判决不能冒充真实模型负例或硬编码金额 ACL。见[公司采购回归](../../src/server/__tests__/cyberpunk-company-settlement.test.ts)。

这项回归还揭示失败响应会丢失原玩家请求的问题。修复后，NPC 的失败或受阻动作若仍需报告，可以在既有无进展上限内保留同一请求并作下一次选择。公司负例现在确认解释实际送达玩家，未虚构付款。连续两次失败会停止；解释本身未能说出时，不能仅因措辞变化就重置计数。玩家授权拒绝不会获得自动重试机会。这部分只用离线 HTTP 替身验证，见[事故记录 0182](../../docs/postmortems/0182-failed-npc-response-lost-its-player-cause.md)。

**本地延迟。** 修复了事件通知先向每个订阅者复制完整 payload、再按实例过滤和丢弃正文的放大。复用 147 个完整事件、30 个 flush 组与约 20.76 MB 正文，在真实 SQLite / WorldHost 上零联网重放六路实例和十二路订阅：7.874→3.326 秒，无用的完整正文复制 4704→0；两类通知各收到 882 条，顺序和六份世界状态不变。完整 Inspector 查询、制品及机械回放仍保留正文。见[事故记录 0181](../../docs/postmortems/0181-full-ledger-payloads-amplified-live-notifications.md)。

这一结果只证明通知路径的约 58% 改善，不能解释此前全部 300 秒超时。无 UI 订阅时收益很小，模型推理仍可能持续一分钟左右。旧 CPU profile 的首个 17.47 秒采样间隔不支持“监听函数执行了 17 秒”的推断，已从归因中排除。没有采用已观察到可见性退化的精简提示，也没有靠缩小语义批次或提高调用次数加速。

原始请求、输出、耗时、预算与零联网复验结果保存在 Git 忽略的 `.acceptance/targeted-20261017/`；通知压力复现保存在 `.acceptance/final-20261017/`。下面的旧失败数据保持原样，不因为修复而改写为通过。

## 浏览器实玩

经纪人实例 `3d018631-4560-42cb-ac5b-a8efeff7aaf6` 经原提交恢复后，首轮到 revision 3、世界时间 90 秒，运行返回等待玩家决策，无叙述回退。玩家问林恩为什么不愿删歌，以及贝克斯最急的支出。林恩实际说出第二段主歌、半拍鼓点和共同排练的意义；贝克斯实际说明设备分期与手头 1200 欧元。保罗提出谈品牌露出和保留曲目。合同仍未签、款项未转，世界操作只有三次时间推进。

这段有可继续发展的利益冲突和具体人物声音，但前两段反复陈述 9000 / 3600 两份方案，贝克斯到第三段才正面回答支出，节奏仍偏慢。恢复后相关执行记录有 26 次传输完成、无传输失败；输入 504555 token、输出 62319 token，其中推理 52909 token。五个世界裁决分别约 15、53、60、68、78 秒，三段叙述分别约 17、12、11 秒。调用包含并行阶段，不能把耗时相加当成玩家等待时间；从恢复到最终叙述发布实际约 250 秒。这些数值不包含此前暂停的失败执行，也不是完整账户账单。

第二轮根据上述话语，提交本地试播工作母带、检查舞台接口、记录实际听感并请成员反馈。结果到 revision 4 后发生 `local-model-task-failed`；已提交的操作只有时间推进 30 秒，试播记录仍空白，没有证据证明器材试播已经完成。具体裁决为 `player_authorization=outside_scope`：玩家明确提出了这次本地试播，候选也保留了该动作与原话，疑似授权误拒。该调用正常返回、耗时 78.561 秒，没有余额或传输超时问题。证据为执行 `de649fca-9786-41e5-a8c8-066262752f73` 的 Ledger 序列 5767 / 5808。最终存档仍可精确机械回放。这轮不计职业通过，也没有为重试改写玩家原话。

## 工程结果与限制

- 缓存修复减少读取已验证存档和世界定义的重复解析，保留副本隔离、外部变更失效与容量界限。
- 模型 deadline 修复在传输、流读取及 GC 后仍能实际取消请求。真实 HTTP 的超时、主动取消、成功路径有离线回归；修复后能按时记录失败，但并未解决所有调用耗时。
- 同一 265 问完整裁决在服务内三次约 300 秒超时，独立原请求约 68 秒完成。单人采样未重现原六路的大量对象复制，不能把全部延迟归给某一未证实原因。
- 简化推理措辞的对照未采纳：265 问对照更慢，且改变 137 项事实可见性与一项名称可见性。没有用较快的小样本掩盖语义偏差。
- 恢复叙述发现把同场 NPC 行为算作玩家已完成步骤、把发出付款指令说成付款进展的问题。收尾修复从已提交动作的 submission 与 cause 关系区分玩家步骤、因果回应、独立事件和未知关系，并保留实际主体与结果；发布检查保留“发出指令”与“实际到账”的限定。见[事故记录 0179](../../docs/postmortems/0179-recovery-prose-lost-request-provenance.md)。该修复将实例契约升至 33，旧存档保留为证据；上文实模仍是修复前的 schema 32，不宣称新提示词已通过实模验证。

停止服务后的 `debug:doctor` 通过：123 个执行、5913 个事件、1691 个制品、316 个索引调用，索引完整，无孤立项或警告。这是日志完整性证据，不是玩法成功率或完整账单。

收尾修复提交 `13027b22` 的 `npm run check:fast` 完整通过：371 个测试文件、2506 项测试，单元测试耗时 404.67 秒；类型、提示词、算法、调试契约、工作流及六项治理检查全部通过。lint 有三个既有警告、无错误。新恢复回归使用 HTTP stub，验证归属传递、限定语发布、拒绝后的有界重写、保存和重启；它不能证明真实模型必然作出正确语义判断。夜之城生成文件一致性检查，以及夜之城和黑沼的世界校验均通过。独立代码审阅未发现阻断问题。
