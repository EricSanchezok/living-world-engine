# 从调研到可运行世界

本文件是持续编写方案与检查清单，不是引擎变更规格。当前运行内容的实现边界见[作者参考](../authoring/README.md)。

## 先把一条事实编对

每条要进入世界的事实先记录以下字段：

| 字段 | 用途 |
|---|---|
| 稳定 ID 与对象 | 用英文检索键去重，别把中文译名差异写成两个人 |
| 简短主张 | 一个可检验的事实，避免一段话同时掺入五种推断 |
| 来源 ID 与页码/任务阶段 | 能回到具体证据；“某 Wiki 说过”不够 |
| 时代与分支 | 是历史、开局、后期还是玩家选择结果 |
| 主张性质 | 原作、二级初核、待核、原创或规则转译 |
| 真值与知情范围 | 作者知道、当事人知道、公开传闻分别记录 |
| 运行承载 | 地点、人物、物品、资产、承诺、机制或认知 |
| 未解决项 | 不确定则保留缺口，不让模型默补为正典 |

示例：`Jackie 与 Misty 是恋人 / P03 p43 / 劫案前 / 原作已核` 可以支撑两人的既有关系；不能由此推出 `Jackie 向所有刚见面的玩家提供住宿与武器`。后一句需要另外的行为、动机与状态支持。

## 已落实的编写层次

1. **统一时间与版本。** 当前 T0、唯一街头小子 V 已确定；原版序章未混入同一切片。电子游戏与桌游材料的适用边界见[时间切片](timeline.md)和[规则](rules.md)。
2. **全域骨架。** 六城区、恶土、狗镇全部建索引，建立公司、警务、帮派、职业与日常生活的交叉关系。先有完整覆盖图，再按片区加深。
3. **核心关系簇。** 优先写杰克—米丝蒂—维克多、朱迪—艾芙琳、荒坂家族—竹村、流浪者家庭与狗镇情报网。每簇同时处理人物、资源、地点、真值与知情。
4. **职业与生活供给。** 补商户、住户、医务、维修、运输、工厂、媒体等角色。原作未命名的职位可原创填充，但标明来源性质，不替换已有重要人物。
5. **出身实例化。** 十二种出身均已落实资产、关系、技能、目标与开场环境，并完成 1.0.1 的独立真实模型轨迹；当前修改继续按[验收报告](../live-verification.md)标记覆盖范围，旧验收不会自动替新版本背书。
6. **开放事件。** 原作任务转为人物意图、资源与条件。保留可发现的线索与可行动的机会；不写“无论玩家做什么都在第 N 步发生某死亡”。
7. **全域复核与游玩。** 对时间、来源、关系、空间和资源做静态检查，再跑非主角出身的实际行动，看是否真的能经营、调查、合作和离开主线。

这个顺序不限制世界最终规模。角色数量是覆盖结果，不能用先凑到某个数量代替准确关系，也不能用一个可运行街区冒充完成整个夜之城。

## 当前引擎的直接证据

截至本轮检查，[出身契约](../../../src/script/contract.ts)提供展示文案、角色设定、出生地点、机制 profile、关系钩子与风险等字段；[世界主机](../../../src/server/world-host.ts)的 `agentStateFromOrigin` 用 persona 和动机创建主体，初始认知里直接生成自身与出生地点，态度和承诺初始为空；[剧本格式](../../../docs/game-design/script-format.md)描述机制 profile 的数量、量表与能力初始化。

这说明仅填写 `relationship_hooks` 不能当作已经建立了互相认识、产权、库存和合同的证据。当前运行包采用预置身份接管；行为证据见[验收记录](../verification.md)。

当前采用第一条路径；第二条是未来能力扩展的比较对象，不是本次应补造的平行实现：

| 路径 | 优点 | 需要验证的问题 |
|---|---|---|
| 预置身份并接管其 Agent | 原有世界人物可预置资产与认知；可利用现有观察/接管概念 | 能否以合适入口选择、改名和自定义外观；未被选择的身份如何在世界存在 |
| 通用出身初始化模板 | 支持新建个体及不同资产、关系、认知组合 | 需要完整 schema、引用、原子性、双向认知及重复应用防护；不得写成赛博朋克专属分支 |

身份接管的选择与代价见[决策记录](../../../docs/decisions/0248-authored-world-lives-through-agent-takeover.md)。若继续扩展通用初始化并涉及认知隔离、权限或持久化风险边界，按仓库规则从 Approved spec 开始；本研究稿不提供引擎变更批准。

## 具体的完成标准

| 检查 | 应能证明什么 |
|---|---|
| 来源追溯 | 每条原作人物身份、重要关系与关键技术限制都有可定位证据；原创条目标识清楚 |
| 时间一致性 | 没有开局已死的杰克、已被放逐的竹村、凭空装有 Relic 的每个玩家等未来泄漏 |
| 分支一致性 | 一个实例只采用一套互相兼容的事实；原作不同选择的结果不会同时成立 |
| 认知隔离 | 陌生 NPC 不知道玩家或特工秘密；角色也不是作者数据库的朗读器 |
| 空间与通行 | 能说明角色如何抵达、需要什么凭证、哪些人能看到行动 |
| 资产与合同 | 所有出身的财富、工具、共同财产与债务可查且不会重复花用 |
| 双向关系 | 熟人能识别玩家并依据共同经历回应，而非仅玩家知道熟人姓名 |
| 自主生活 | 玩家拒绝第一个委托、避开 V、去别的城区后仍有生活与成长路径 |
| 人物独立 | 原作角色保有目标与私人关系；离开玩家视野也不变成静止任务牌 |
| 真正开放的未来 | 改变资源、救下人物、让交易失败后，世界后续与改变保持一致 |

这些是持续验收项。已执行检查的结果与未验证范围以[验收记录](../verification.md)为准，不能由清单存在推断全部完成。
